# forge-cli — Release plan v0.3.0

Scope: remote-resolved-state as source of truth. Conversation views default to unresolved threads, resolution happens through the CLI, and downloads become explicit `pull` verbs writing into `.forge/cache/`. No local seen/unseen state anywhere; saved copies are plain dumps requiring no interpretation. This replaces the seen/unseen design that originated in `plans/proposals/v0.3.0-unseen-comments.md`; that file and its counterpoint remain as history.

Model change, stated plainly: v0.3.0 tracks *unresolved*, not *unread*. A reviewer never resolving a nit keeps it visible indefinitely, which is correct for the fix-and-respond loop; the unread loop is v0.4.0 territory (likely Forgejo notification read flags).

## 2. Command surface

```
forge pr list [--state --page --limit]        # PR rows, table (TTY), no downloads
forge pr get N                                # raw PR JSON, stdout only
forge pr conv N                               # conversation view+fetch:
                                              #   reviews having >=1 unresolved
                                              #   comment, unresolved comments
                                              #   first within each review;
                                              #   --all shows everything;
                                              #   --min-unresolved N filters
forge pr review list N                        # rows: id, user, state,
                                              #   unresolved/total counts
forge pr comment resolve <id>                 # root comment id of a thread
forge pr comment unresolve <id>
forge pr resolve-all N [--review R] [--yes]
forge pr create ...

forge issue list / get N                      # unchanged surfaces
forge issue close N                           # PATCH issues/N {"state":"closed"}
forge issue open N                            # {"state":"open"}
forge issue pull N                            # dump issue payload incl. comments

forge pr pull N                               # fetch + write conversation dump,
                                              #   prints receipt; no payload on
                                              #   stdout ever
forge cache path / flush                      # guarded per §5
```

Removed: `save pr-conversation|issue`, `pr conversation`, `pr new`, bare-number `pr <N>`. Deprecation migration: none required (pre-release tool), but `pr conversation N` errors with exit 2 and a hint naming `pr conv`.

Notes:

- Reviews are included in `conv` when **any** comment has `resolved == false`. Ordering: oldest `submitted_at` first across reviews; within a review, unresolved before resolved (path, position, id ties). `--all` drops the filter, keeps ordering.
- `resolve-all` without `--yes` prints the ids it would resolve and exits 0, mutating nothing. With `--yes`: collect per-id results, stderr summary (`resolved: 40, failed: 2` with server messages verbatim, already-resolved reported skipped), exit 1 on any failure. Reruns are safe because resolution is idempotent.
- Resolve endpoints operate on root thread comment ids; replies carry no independent state and yield server errors surfaced verbatim per the APIError contract. If the server lacks the endpoint (404 pattern distinct from bad-id), probe once at startup of the verb and degrade loudly with a hint about server version.
- `pr get` and every view verb stay strictly side-effect free. Only `pull` writes.

## 3. Remote anchors kept, computation dropped

Struct extensions land as planned (`Resolved` is the entire filter; commit/path/position fields make table views show path+position rather than hunk blobs, and finally surface the diff origin the original release note asked about). No computed status block, no `git cat-file`/`merge-base` machinery, no `BranchSync`; that served unseen tracking and dies with it.

Issue comments have no commit anchor and no resolution mechanism (`resolved` is a PR review-comment concept); issue-level tracking uses whole-issue close/open only.

## 4. Output contract

Global flags `--json` and `--table|-t`, registered in `internal/cli`, stored on Ctx; conflicting both exits 2. Each command declares a default kind:

- Table default (TTY human views): `pr list`, `pr review list`, `conv`'s rendered sections, `issue list`.
- JSON default: `pr get`, mutation receipts (`resolve|unresolve`, `resolve-all` summary), `pull` receipts, error envelopes everywhere.
- TTY detection as unix convention: when stdout is not a TTY, table-default commands emit machine JSON instead of table art, unless `--table` forces it explicitly. Colour/decoration applies only on TTYs.
- `-v` stays request diagnostics on stderr only; it never reshapes stdout.

Renderer lives in `internal/table` (column specs per view type shared by pr and issue paths; repeated glue acceptable where specs diverge).

## 5. Pull and cache layout

Pull replaces the save family outright:

- Single invocation per item: fetch typed structs via existing fetchers, write, print receipt. Receipt shape:
  ```json
  {"path": ".forge/cache/prs/<repo>-42.json", "items": 31, "reviews": 5, "unresolved": 2}
  ```
- Write semantics: overwrite `<repo>-<N>.json` per target (one current copy per item, snapshot-append behaviour removed along with `save`). Print receipt on success; on write failure loud non-zero with resolved dir named.
- Layout under the repo-local `.forge` dir:
  ```
  .forge/config.toml      # committable project defaults (unchanged behaviour)
  .forge/cache/prs/       # gitignored, <repo>-<N>.json
  .forge/cache/issues/    # gitignored
  ```
- `.gitignore` ships `.forge/cache/` from `forge init`-style setup guidance in the README; config remains committable per PRD section 7.
- Config: `[savedir] pr-conversation = ".forge/cache/prs"` / `issue = ".forge/cache/issues"` seeded defaults; global override may point anywhere including XDG-style `~/.local/state/forge/<host>/<o>/<r>/` (explicit 0.2.0 decision whether that becomes default).
- Flush guard: `cache flush` refuses any directory whose contents would include `config.toml` or the resolved global config file, regardless of how savedirs are configured.

Deleted: plans for `internal/state`, `internal/marker`, `gitctx/sync.go`, snapshot logic (never built).

## 7. Build order

1. **Anchors + verification**: struct fields, live-server pagination/resolved-field verification (blocking), paginated helpers, fixture tests
2. **Views**: `table` package, `--json/--table|-t` globals with TTY defaults, `pr list`/`pr get`/`pr review list`, `pr conv` with unresolved predicate and ordering
3. **Resolution verbs** + `resolve-all` dry-run flow, idempotency handling, endpoint-probe degradation
4. **Pull + cache**: rename/restructure save → pull, overwrite store function, `.forge/cache/` seeding, flush guard, receipts
5. **Issues**: `close`/`open`

Each stage ships green independently; stages 1 and 4 stand alone even if later stages slip past 0.3.0.
