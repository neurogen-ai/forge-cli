# forge-cli — Release plan v0.4.0

Scope: complete the PR conversation loop with write verbs and the raw diff view. Every verb here is thin HTTP over endpoints we already know exist; no local state, receipts follow the pull pattern where anything mutates.

Release split: the generic discovery work that previously lived in this note moved out. `forge api`, `forge search issues|prs`, and the single-shot Starship status check are v0.5.0 (`plans/releases/v0.5.0.md`); the auto-sync service idea is v0.6.0 (`plans/releases/v0.6.0.md`). Implementation detail lives in `plans/implementation/v0.4.0.md`.

## 1. Scope checklist

- [x] `forge pr review submit N --state approve|request-changes|comment [--body T]`
- [x] `forge pr comment add N --body T` / `forge issue comment add N --body T`
- [x] `forge pr close N` / `forge pr reopen N` / `forge pr ready N`
- [x] `forge pr diff N` (Forgejo `.diff` suffix URL) + `--patch`, `--out` writing below the `pr-conversation` savedir
- [x] `forge pr merge N --merge|--squash|--rebase [--delete] [--subject S] [--body T]`

## 2. Verbs

### review submit

POST `/repos/{o}/{r}/pulls/{index}/reviews` with body `{event, body}`. `--body` required for `request-changes`; validation error exits 2 otherwise. Output: JSON receipt of the created review (id, state). Reuses `Review` struct extended in 0.3.0.

### comment add

POST `/repos/{o}/{r}/issues/{index}/comments` works for both PRs and issues in Forgejo (PRs are issues underneath); both spellings route to one client method. JSON receipt back (id, HTMLURL).

### close / reopen / ready

- PRs: PATCH `/repos/{o}/{r}/pulls/{index}` `{"state": "closed"|"open"}`.
- `pr ready N`: PATCH `/pulls/{index}` `{"draft": false}`; server versions lacking draft support surface the message verbatim, exit 1.
- Issues already have close/open from 0.3.0 stage 5.

### diff

GET `/repos/{o}/{r}/pulls/{index}.diff` (and `.patch`). Text/plain response; default prints to stdout byte-for-byte (it IS a view verb — pure), `--out` writes `<repo>-<N>.diff` (or `.patch`) below the `[savedir] pr-conversation` directory (seeded at `.forge/cache/prs/`), replacing any previous copy for that PR and format. Receipt style printed when written.

Careful: this endpoint bypasses the JSON client (`Client.Do` decodes JSON); v0.4.0 added `Client.DoRaw`, the shared raw-text transport, for it.

### merge

POST `/repos/{o}/{r}/pulls/{index}/merge` with `Do` field values matching gh semantics: `merge|squash|rebase`. Exactly one strategy flag required; flags map directly; `--delete` then DELETEs `/repos/{o}/{r}/git/refs/heads/<head>` after a successful merge (never after a failed one; a failed delete after a successful merge still prints the receipt with `head_deleted: false`). Conflict/WIP/unprotected failures come back as non-2xx: print server message verbatim, exit 1, never retry automatically. Merge requires up-to-date base handling per Forgejo defaults; do not invent auto-update behaviour (documented anti-goal pending `update-branch` demand).

## 3. Conventions carried from 0.3.0

- View/pull split unchanged: all read paths stay pure; mutating verbs emit JSON receipts; conflicting global `--json/--table/-t` still exit 2. Receipt commands are JSON-only and reject `--table` centrally.
- No prompts, no confirmations: destructive-ish verbs (merge, close, delete ref) are explicit single-shot; dry-run not needed because blast radius is one object unlike resolve-all.
- Exit codes unchanged; server messages verbatim through APIError.

## 4. Build order

Per `plans/implementation/v0.4.0.md`:

1. Branch A — review submission and issue-backed comments (API methods, `pr review submit`, both `comment add` spellings)
2. Branch B — PR state verbs (PATCH methods, `pr close` / `pr reopen` / `pr ready`)
3. Branch C — raw diff and file output (`Client.DoRaw`, filename-owned store writes, `pr diff`)
4. Branch D — merge (merge and ref methods, `pr merge` with `--delete` ordering)
5. Branch E — release boundary docs and acceptance battery

Landed outside the feature branches but shipped in this release: `fix(cli)` — longest-match command dispatch (commit 0b7cc23). The registry previously joined at most two argv tokens, so every three-token command path (`pr review submit`, `pr comment add`, `issue comment add`, and the older `pr review list`, `pr comment resolve`) was unreachable from the binary.
