# forge-cli — Release plan v0.4.2

Scope: the remaining thin HTTP verbs that round out object management, none of which block anything in 0.4.0. All follow established conventions (JSON receipts on mutations, table defaults on TTY for lists, pure views elsewhere).

Moved here from v0.4.1, which was re-scoped as the batch-correctness release after a real-world failure of `create-batch` (see `plans/releases/v0.4.1.md`).

## 1. Scope checklist

- [x] `forge pr edit N [--title T] [--body B]` / `forge issue edit N [same]`
- [x] `forge label list`; `forge issue label add|remove N --label name...`
- [x] `forge pr browse N` / `forge issue browse N` / `forge repo browse`
- [x] `forge release list | get TAG | download TAG [--asset NAME]`
- [x] central version constant: move the release version into one high-in-tree location (repo root `version.go`, package `forge`) and have `forge version` read it instead of the hard-coded `forge-cli v0.1` string in `cmd/forge/main.go`; version numbers change only in that one place

## 2. Notes

- edit: PATCH pulls/issues endpoints already used by close/reopen; same method, more fields.
- labels: ListLabels exists from v0.1; add CreateLabel/DeleteLabel as needed, resolve names to ids like issue create does. Label add/remove is POST/DELETE on `/issues/{index}/labels`.
- browse: print `HTMLURL` (already carried on most structs) or open via `$BROWSER` when `--open` given; never auto-opens.
- releases: GET `/repos/{o}/{r}/releases[/{tag}]`, assets download straight to `.forge/cache/releases/` with pull-style receipts (overwrite per filename). No upload/create until someone actually asks; authoring releases is rare from a CLI agent loop.
- version constant: `cmd/forge/main.go` still prints the placeholder `forge-cli v0.1`. One repo-root `version.go` (`package forge`, exported `Version`) is the single source; `forge version` is its only consumer today, so reflection is one import. Bump `forge.Version` as the first commit of each release so the binary, `git tag`, and the release docs agree.

## 3. Defer

`repo view/edit` and any org/team surface: no consumer story yet.

## Acceptance notes (v0.4.2)

Automated battery on branch `v0.4.2-pr3` (history: Branch A edit verbs →
Branch B labels → Branch C browse → Branch D releases, seven commits with one
fixup, then Branch E version constant) — all green across every package:
`go vet ./...` (clean), `gofmt -l .` (empty output), `go build ./...`,
`go build -o /tmp/forge-bin ./cmd/forge`, `go test ./...` (ten packages, one
with no test files; slowest is `internal/cmds`). No third-party dependencies
were added; `go.mod` still names only the module.

Binary battery, run against the freshly built binary inside this repository:

- `forge version` prints `forge-cli v0.4.2` and exits 0, reading the
  `forge.Version` constant from repo-root `version.go`. The only consumer of
  the constant is the print in `cmd/forge/main.go`; no `forge-cli v0.1`
  string survives in any Go file.
- Every new help page exits 0: `pr edit -h`, `issue edit -h`, `label list -h`,
  `issue label add -h`, `issue label remove -h`, `pr browse -h`,
  `issue browse -h`, `repo browse -h`, `release list -h`, `release get -h`,
  `release download -h`.
- `cache path` lists `.forge/cache/releases` alongside the existing
  `issues` and `prs` savedirs, so `cache flush` covers release assets
  automatically.

Spot checks, each pinned by an httptest-backed test that was run as part of
`go test ./...`:

- `pr edit`/`issue edit` reject an invocation with no non-empty
  `--title`/`--body` before any HTTP request. `internal/cmds/edit_test.go`,
  `TestEditRejectsEmptyFlagSet` asserts the server saw zero requests.
- `issue label add` sends one POST carrying every resolved id in input order.
  `internal/cmds/labels_test.go`, `TestIssueLabelAddOnePOSTWithAllIDs`.
- `issue label remove` stops on the first failed removal and prints no
  receipt. `internal/cmds/labels_test.go`,
  `TestIssueLabelRemoveStopsOnFirstFailure`.
- Release download refuses an off-host asset URL before the token is sent.
  `internal/api/client_test.go`, `TestDownloadRejectsOffHostBeforeRequest`,
  and the command-level `internal/cmds/releases_test.go`,
  `TestReleaseDownloadOffHostAssetRefuses`.
- A mid-batch download failure leaves earlier files in place and prints no
  receipt. `internal/cmds/releases_test.go`,
  `TestReleaseDownloadMidBatchFailureKeepsFilesPrintsNoReceipt`.

Live-gated items (no Forgejo instance / no network at release-cut time):

- Real release payloads with asset redirects were not exercised. The download
  path is covered by fixtures: `internal/api/client_test.go`
  (`TestDownloadRejectsOffHostBeforeRequest`, `TestDownloadNetworkFailureIsTagged`)
  and `internal/cmds/releases_test.go` (list, get, download, receipt, and
  failure-leg tests against httptest servers).
- An actual browser launch was not exercised. `openInBrowser` policy (no
  shell, URL as final argument, missing browser and non-zero exit are
  runtime errors) is covered by `internal/cmds/browse_test.go`.

Descope deferral: `repo view/edit` and any org/team surface stay out of this
release (no consumer story yet, §3). The only repository-surface addition is
the `HTMLURL` decode and `repo browse`; no repository view or edit command
exists on any branch.
