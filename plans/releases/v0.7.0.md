# forge-cli — Release plan v0.7.0

Scope: release engineering + repo admin. Everything needed to provision repos, and to provision and cut releases for them, from the CLI — plus the Forgejo Actions write-side (dispatch, cancel, re-run) that pairs with the secrets/variables the dispatched workflows consume.

Two documented deferrals are reversed here, with reasons on record: release create/edit/upload ("no upload/create until someone actually asks" — demand now exists: agents cutting tagged releases) and `repo view` ("no consumer story yet" — repo metadata + `default_branch` is what scripts need to construct checkout URLs).

## 1. Scope checklist

- [ ] `forge release create TAG [--title T] [--notes N] [--target REF]` / `forge release edit TAG` / `forge release delete TAG` / `forge release upload TAG --asset FILE...`
- [ ] multipart asset upload: the first multipart request in `internal/api`. Price this as new transport machinery, not just another verb — `Client.Do` is JSON-only and `DoRaw` is verbatim bytes; upload needs its own request construction following the shared-helper pattern.
- [ ] Forgejo Actions dispatch/cancel/re-run: `forge actions dispatch WORKFLOW [--ref R] [--input K=V]...`, `forge actions cancel RUN`, `forge actions rerun RUN`. Run IDs share the space `pr checks` reads (v0.6.0), so an agent can dispatch then gate on the result.
- [ ] Actions secrets and variables: `secret set NAME` (value via stdin/flag, write-only — never printed back), `secret delete NAME`, `secret list` (names only), same shape for `variable`. A dispatched workflow consumes what this release configures.
- [ ] `forge repo view` — repository metadata incl. `default_branch` (already on the fetched type from v0.3.1) as a small JSON view.
- [ ] `forge repo create NAME [--owner O] [--private] [--desc D] [--default-branch B] [--auto-init]` — creates a repo under the authenticated user (`POST /user/repos`) or, when `--owner` names an org, under that org (`POST /orgs/{org}/repos`). Prints a `{full_name, html_url, default_branch}` receipt so scripts can chain straight into `pr create`. `--auto-init` seeds a README; no template/license selection in v0.7 scope.
- [ ] ssh-key / gpg-key management: `ssh-key add|delete|list`, `gpg-key add|delete|list` — the CLI's only user-account surface; provisioning keys for fresh agent environments is the use case.

## 2. Notes

- Actions endpoints are the most version-dependent surface in the plan (run list/cancel/rerun vary by Forgejo version). Probe-first applies here more than anywhere; if dispatch is unavailable, ship `pr checks` reads only and record the gap.
- Secret values are write-only by server contract: receipts carry the key name and a `{"name": ..., "updated": true}` shape, never the value.
- Workflow dispatch targets default branch refs unless `--ref` is given; inputs are repeatable `K=V` pairs, matching `forge api`'s `--q k=v` convention.
- `repo view` also un-defers part of the v0.4.2 §3 parking ("repo view/edit deferred — no consumer story yet"); `repo edit` stays parked.

## 3. Parked

- Webhook management (one-time configuration, not loop work)
- Actions cache management, workflow authoring/editing
- Org/team surfaces and projects (inherited deferral from v0.4.2)
