# forge-cli — Release plan v0.4.2

Scope: the remaining thin HTTP verbs that round out object management, none of which block anything in 0.4.0. All follow established conventions (JSON receipts on mutations, table defaults on TTY for lists, pure views elsewhere).

Moved here from v0.4.1, which was re-scoped as the batch-correctness release after a real-world failure of `create-batch` (see `plans/releases/v0.4.1.md`).

## 1. Scope checklist

- [ ] `forge pr edit N [--title T] [--body B]` / `forge issue edit N [same]`
- [ ] `forge label list`; `forge issue label add|remove N --label name...`
- [ ] `forge pr browse N` / `forge issue browse N` / `forge repo browse`
- [ ] `forge release list | get TAG | download TAG [--asset NAME]`

## 2. Notes

- edit: PATCH pulls/issues endpoints already used by close/reopen; same method, more fields.
- labels: ListLabels exists from v0.1; add CreateLabel/DeleteLabel as needed, resolve names to ids like issue create does. Label add/remove is POST/DELETE on `/issues/{index}/labels`.
- browse: print `HTMLURL` (already carried on most structs) or open via `$BROWSER` when `--open` given; never auto-opens.
- releases: GET `/repos/{o}/{r}/releases[/{tag}]`, assets download straight to `.forge/cache/releases/` with pull-style receipts (overwrite per filename). No upload/create until someone actually asks; authoring releases is rare from a CLI agent loop.

## 3. Defer

`repo view/edit` and any org/team surface: no consumer story yet.
