# Implementation plan, v0.3.1

## Context

**What exists:** after v0.3.0, forge-cli has remote-resolved-state conversation views (`pr conv`, `internal/cmds/pr_conv.go`), resolution verbs, `pull`/`cache` with receipts, the global `--json`/`--table` output contract, and a hand-rolled command registry. `pr create` (`internal/cmds/pr.go:25`) requires `--title` and resolves `--base` only from flag → `$FORGE_BASE` → `[defaults].base`. Bare `forge pr` help is generated generically from member summaries (`internal/cli/help.go` `PrintGroupPage`). gitctx exposes only `Detect` and `CurrentBranch`; the API client has `CreatePullRequest`, `BranchExists`, and the `List[T]` pagination helper, but no repository fetch, so `default_branch` is unreachable. This release implements `plans/releases/v0.3.1.md`: conv becomes the PR landing page, `pr create` infers title and base, and `pr create-batch` opens PRs for matching local branches with a dry-run default.

**Files touched:** `internal/gitctx/repo.go`, `internal/api/types.go`, `internal/api/repo.go`, `internal/cli/help.go`, `internal/cli/registry.go`, `cmd/forge/main.go`, `internal/cmds/pr.go`, `internal/cmds/pr_landing.go` (new), `internal/cmds/pr_batch.go` (new), plus tests: `internal/gitctx/repo_test.go`, `internal/api/repo_test.go`, `internal/cli/help_test.go`, `internal/cmds/pr_test.go`, `internal/cmds/pr_batch_test.go` (new), `README.md`, `plans/releases/v0.3.1.md`.

**Depends on:** `plans/releases/v0.3.1.md` (the authority for behaviour and all precedence/failure decisions; that doc resolves the oracle questions and is not restated here), `plans/PRD.md` §5-§10 (precedence, exit codes, error contract), `plans/implementation/v0.3.0.md` (test-fixture and receipt shapes this builds on).

**Precondition:** v0.3.0 is merged and on main. Cut every branch below from main after that point. Merging to main is out of scope for every branch in this plan and happens separately after review.

**Decisions this plan pins** (all trace to the release doc, kept here only as compile-time shapes):

- gitctx is the single place git is shelled out to; cmds never runs `git` directly. New requirement = new gitctx helper, one file changed.
- `pr create-batch` reuses the `create`-family inference through one shared entry point (`resolveCreateDefaults`), so a change to title/base rules lands in one place for both commands.
- Batch receipts and dry-run plans are the same type (`[]BatchReceiptItem`), so the dry-run output is exactly the post-run output minus `url`/`number`.
- The PR landing page is registered as a group-page override carrying a command index built from `PRCommands()` at registration time, so a new pr subcommand shows up in the index with no edit.

---

## Goals

1. `forge pr` and `forge pr -h` print the conv help page plus an auto-derived index of the other pr verbs; per-subcommand help is unchanged.
2. `pr create` works with no flags: title comes from the branch tip's commit subject, base falls back through config → `origin/HEAD` → server `default_branch`.
3. `forge pr create-batch PATTERN` opens PRs for matching local branches, dry-run by default, `--yes` to post, stop on first failure, JSON receipt array.

## Success criteria

- `forge pr` output starts with `use: forge pr conv` and lists every non-conv pr subcommand by name and summary; `forge pr conv -h` still prints the original conv page verbatim.
- `forge pr create` on a branch with a unique commit and no flags posts exactly one PR titled with the commit subject; with `--title` given, no git call for the subject happens.
- Base resolution never hardcodes `main`: a repo with no `origin/HEAD` and a server reporting `default_branch: "trunk"` targets `trunk`.
- `forge pr create-batch 'v0.4.0*'` without `--yes` prints the JSON plan and posts nothing; with `--yes`, a failing POST stops the batch and prior successes stay in the receipt.
- `go vet ./...`, `gofmt -l .`, `go build ./...`, `go test ./...` green at every verified step; no third-party dependencies.

## Tests

Inline per step; each step's Verify block names the commands to run. gitctx tests use the temp-repo pattern in `internal/gitctx/repo_test.go` (`requireGit`, `initRepo`); cmds tests use the `httptest` `testCtx` fixture in `internal/cmds/pr_test.go`. Unit suites never require network. Live-server verification of `default_branch` happens only through the existing client tests against the fixture server shape; no probe script this release.

# Branch A, gitctx helpers

Pure `internal/gitctx` work, no command compiles differently afterwards. Gates Branch C.

### Step A1: subject, ancestry, and branch enumeration

`internal/gitctx/repo.go`, append below `CurrentBranch`:

```go
// CommitSubject returns the first line (subject) of the commit at ref, or ""
// when ref does not resolve or has no message. Trailing whitespace trimmed.
func CommitSubject(root, ref string) string {
	out, err := git(root, "log", "-1", "--format=%s", ref)
	if err != nil {
		return ""
	}
	return out
}

// UniqueCommitCount returns how many commits HEAD-side has that base-side
// lacks (`git rev-list --count base..head`). Error when either ref does not
// resolve; the caller owns deciding what "missing base" means.
func UniqueCommitCount(root, base, head string) (int, error) {
	out, err := git(root, "rev-list", "--count", base+".."+head)
	if err != nil {
		return 0, err
	}
	return strconv.Atoi(out)
}

// LocalBranches lists short names of all local branches
// (`git for-each-ref refs/heads --format=%(refname:short)`), empty when none.
func LocalBranches(root string) []string {
	out, err := git(root, "for-each-ref", "refs/heads", "--format=%(refname:short)")
	if err != nil || out == "" {
		return nil
	}
	return strings.Split(out, "\n")
}
```

Add `"strconv"` to imports. No glob handling here: pattern matching stays with the caller (Step E1), because git's for-each-ref glob would also match remote-tracking names under some invocations and the caller needs control over empty-match behaviour.

Tests in `internal/gitctx/repo_test.go`, using `initRepo` and extra `git` invocations in-test to build two branches: subject from a branch tip, `UniqueCommitCount` across branches (1, then 2 after a second commit), `LocalBranches` contents and ordering, `CommitSubject` of a nonexistent ref → `""`, `UniqueCommitCount` with a missing base ref → error. Detached HEAD is covered implicitly: every helper takes a ref, never `HEAD`-only.

Out of scope: remote-branch listing, merge-base, creation-date ordering, anything reading config.

Verify: `go test ./internal/gitctx/` and `gofmt -l internal/gitctx` (empty).

### Step A2: remote default branch

`internal/gitctx/repo.go`:

```go
// RemoteHead returns the short branch name refs/remotes/origin/HEAD points
// at, or "" when unset (never created, shallow clone, detached ref).
// Read-only: never runs `git remote set-head`.
func RemoteHead(root string) string {
	out, err := git(root, "symbolic-ref", "--short", "refs/remotes/origin/HEAD")
	if err != nil {
		return ""
	}
	// symbolic-ref --short yields "origin/main"; strip the remote prefix.
	_, branch, _ := strings.Cut(out, "/")
	return branch
}
```

Tests in `internal/gitctx/repo_test.go`: repo where a test helper creates `refs/remotes/origin/HEAD` pointing at `origin/main` → `"main"`; fresh `initRepo` with no remote refs → `""`. Building the ref in-test: `git update-ref refs/remotes/origin/main <sha>` plus `git symbolic-ref refs/remotes/origin/HEAD refs/remotes/origin/main`, added as a small test helper in the same file (`setOriginHead(t, dir, branch string)`).

Out of scope: server `default_branch` (Branch B), any mutation of git state.

Verify: `go test ./internal/gitctx/`.

// GetRepository fetches one repository. Non-2xx surfaces through the

func (c *Client) GetRepository(o, r string) (*Repository, error) {
	var repo Repository

# Branch C, pr create inference

Gates on A and B. Touches `internal/cmds/pr.go` only.

### Step C1: resolveCreateDefaults

New file `internal/cmds/pr_create_defaults.go`:

```go
// createDefaults carries the fully-resolved inputs to POST /pulls. Title and
// Base are proven non-empty by Resolve; Head may still be "" only when the
// caller cannot run inside a repo (pr create errors before constructing
// createDefaults in that case).
type createDefaults struct {
	Title, Head, Base string
}

// ResolveCreateDefaults applies the release §3 precedence for title, head,
// and base. apiBase fetches the server default branch (may be nil in tests).
func ResolveCreateDefaults(titleFlag, headFlag, baseFlag string, repo *gitctx.Repo, cfgBase string, apiBase func() (string, error)) (createDefaults, error)
```

Precedence, first match wins, exactly as `plans/releases/v0.3.1.md` §3 pins:

- Title: `titleFlag` → `CommitSubject(repo.Root, "HEAD")`. Empty subject, or `UniqueCommitCount(repo.Root, base, "HEAD") == 0` after base resolution, → error `{Code: cli.ExitUsage, Msg: "no commits to title this pull request", Hint: "pass --title, or commit on the branch first"}` (the count check runs only when the title was inferred, and only after base is known).
- Head: `headFlag` → `$FORGE_HEAD` → `CurrentBranch` (existing logic, moved here verbatim).
- Base: `baseFlag` → `$FORGE_BASE` → `cfgBase` → `RemoteHead(repo.Root)` → `apiBase()` (returns `Repository.DefaultBranch` via `GetRepository`) → error `{Code: cli.ExitRuntime, Msg: "no base branch", Hint: "cannot determine base branch; pass --base"}`.

`internal/cmds/pr.go` `prCreateCmd.Run`: delete the inline title/require/base blocks; construct the closures and call `ResolveCreateDefaults`; keep `mapCreateErr` and the `writeJSON` tail untouched. The `Summary()` string drops " (--title required)".

Tests in `internal/cmds/pr_test.go` (new test file `internal/cmds/pr_create_defaults_test.go` using the httptest fixture for `apiBase`): explicit `--title` wins without touching git (pass a `repo` pointing at a temp dir and assert no inference when title given); empty-commit-branch errors exit 2; base chain falls through each level (config empty → RemoteHead `""` → apiBase `trunk`); apiBase failure surfaces as the exit-2 base error.

Out of scope: `--head` precedence changes, `mapCreateErr`, create-batch (Branch E), any config key additions.

Verify: `go test ./internal/cmds/ ./internal/cli/ && go build -o /tmp/forge ./cmd/forge && go vet ./...`.

### Step D2: PR landing page

New file `internal/cmds/pr_landing.go`:

```go
// PRGroupHelpText renders the pr family landing page: the conv help page
// verbatim, then an index of the other pr subcommands built from the
// registered members at call time, so a newly added verb shows up without an
// edit here.
func PRGroupHelpText(reg *cli.Registry) string {
	conv := prConvCmd{}
	page := conv.HelpPage()
	var idx strings.Builder
	for _, c := range reg.Sorted() {
		name := c.Name()
		if !strings.HasPrefix(name, "pr ") || name == "pr conv" {
			continue
		}
		fmt.Fprintf(&idx, "  %-24s %s\n", strings.TrimPrefix(name, "pr "), c.Summary())
	}
	return page + "\nOther pr commands:\n\n" + idx.String() +
		"\nrun `forge pr <subcommand> -h` for details\n"
}
```

`cmd/forge/main.go`, after the existing `reg.Register(cmds.PRCommands()...)` call:

```go
	reg.SetGroupPage("pr", cmds.PRGroupHelpText(reg))
```

Tests in a new `internal/cmds/pr_landing_test.go` with a real registry registering `PRCommands()`: page starts with `use: forge pr conv`, contains one line per non-conv verb (`create`, `list`, `get`, `review list`, `comment resolve`, `comment unresolve`, `resolve-all`), and the conv `--all` wording survives verbatim.

# Branch E, create-batch

Gates on C. Touches `internal/cmds` only.

### Step E1: dry-run plan

New file `internal/cmds/pr_batch.go`:

```go
// BatchReceiptItem is one planned or completed PR creation. In a dry-run
// plan only Branch/Title/Base are set; after --yes, URL/Number fill in on
// success and Error carries the server's message verbatim on failure. The
// plan and the receipt are the same type so the two outputs never drift.
type BatchReceiptItem struct {
	Branch string `json:"branch"`
	Title  string `json:"title"`
	Base   string `json:"base"`
	Number int64  `json:"number,omitempty"`
	URL    string `json:"url,omitempty"`
	Error  string `json:"error,omitempty"`
}

type createBatchCmd struct{}

func (createBatchCmd) Name() string    { return "pr create-batch" }
func (createBatchCmd) Summary() string { return "open pull requests for branches matching a pattern (dry-run by default, --yes to post)" }
func (createBatchCmd) RequiresAPI() bool { return true }
```

`Run` flow, in order:

1. Parse `PATTERN` as the first non-flag arg (missing → `ExitUsage`, hint naming the usage). Parse `--yes` with `flagBool`, `--base` with `flagValue`, `--body` with `flagValue`.
2. Collect branches: `gitctx.LocalBranches(ctx.Repo.Root)` (nil repo → `ExitContext` "must run inside a repository"), filter with `path.Match(pattern, name)` (`path`, not `filepath`: branch globs are slash-agnostic). No matches → `ExitUsage` "no branches match PATTERN". Sort with `sort.Strings` (lexically, per the release doc).
3. Preflight: for each branch, build title via `CommitSubject(root, branch)`; skip-and-record `{Branch: b, Error: "no commit subject"}`-style failures by *dropping* them from the plan but listing them in a stderr line `skipped: <branch> (<reason>)`, because the release doc pins that zero-commit branches are reported and prevent execution only when they invalidate the whole run — here one bad branch does not block the others, it is skipped loudly. Empty plan after skips → `ExitRuntime`.
4. Resolve base once via `ResolveCreateDefaults("", "HEAD→unused", baseFlag, ...)` reusing Branch C's resolver with `apiBase` set. Per-branch head is the branch name itself.
5. Emit the plan: `writeJSON(ctx.Stdout, items []BatchReceiptItem)`, exit 0, when `--yes` is absent.

Commit the plumbing (steps 1-5) first. Receipt posting is Step E2; the dry-run path is complete and testable without it.

Tests in `internal/cmds/pr_batch_test.go`: glob matching (`v0.3.0*` matches `v0.3.0-a`, not `release/v0.3.0`), lexical ordering of the plan, skipped-branch stderr line, no-POST guarantee (fixture server that fails the test if `POST /repos/.../pulls` is hit during a dry run), plan JSON shape.

Out of scope: `--yes` posting, dependency-ordered stacks, pushing unpushed branches, duplicate-PR detection, `--review`-style filters.

Verify: `go test ./internal/cmds/ && go build -o /tmp/forge ./cmd/forge && /tmp/forge pr create-batch 'no-such-*'` exits 2 with the no-match error.

### Step E2: --yes posting

Extend `createBatchCmd.Run` after the plan is built: when `--yes`, iterate items in order; for each, call `ctx.API.CreatePullRequest` with `Head: item.Branch, Title: item.Title, Base: item.Base, Body: bodyFlag`. On success fill `Number` (from the returned `*api.PullRequest`, field `Number int64` in `internal/api/types.go` — verify the json tag there and use its exact field) and `URL` (`PullRequest.HTMLURL`, same check). On the first failure: set `Error` to the server's message via the existing `serverMessage` helper (`internal/cmds/pr.go`), append the item, `return writeJSON(...)` with the partial receipt and `&cli.Error{Code: cli.ExitRuntime, Msg: "batch stopped: <branch> failed"}` — print the receipt before returning the error so the receipt reaches stdout and the error reaches stderr through the normal error path; order the code accordingly (write receipt to ctx.Stdout first, then return the cli.Error). No retries, no rollback (release doc §4).

Tests: fixture server succeeding for the first two POSTs, failing the third with a JSON body message → receipt has three items, third carries `Error`, run returns non-zero; server failing on the first POST → receipt has one item with `Error`; second run with `--yes` after a partial batch is the caller's business (no state kept, asserted by the test using a fresh `testCtx`).

Out of scope: continuing past a failure, transactional semantics, per-branch body inference.

Verify: `go test ./internal/cmds/ && go vet ./... && gofmt -l internal` (empty).
