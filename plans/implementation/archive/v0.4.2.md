# Implementation plan, v0.4.2

## Context

**What exists:** after v0.4.1, main has the typed Forgejo client (`Do`, `DoRaw`, the generic `List` paginator, `patchPull`), the registry with longest-match dispatch, TTY-aware JSON/table output, `store.WriteFile`, and cached pulls and diffs with receipts. Commands follow one shape: small parameterized command structs over typed API methods, receipts only after success. The binary still prints the hard-coded `forge-cli v0.1`.

**Areas touched:** `internal/api` (new `releases.go`; `pulls.go`, `issues.go`, `client.go`, `types.go` extended), `internal/cmds` (new `edit.go`, `labels.go`, `browse.go`, `releases.go`, `savedir.go`; `views.go`, `pull.go`, `pr_diff.go`, `cache.go` touched), `internal/config`, a new repo-root `version.go`, `cmd/forge/main.go`, `README.md`, and `plans/releases/v0.4.2.md`.

**Depends on:** `plans/releases/v0.4.2.md` is the authority for scope and behaviour. `plans/PRD.md` §§5-10 covers precedence, output, and the error/exit-code contract. `plans/implementation/v0.4.1.md` supplies the current sequencing and acceptance style; `plans/implementation/archive/v0.3.1.md` the registry and list-rendering conventions. No `design/*` decisions exist; all proposals are archived v0.3.0 material, none active here.

**Preconditions:** v0.4.0 and v0.4.1 are merged on main; cut every branch from that baseline. Merging to main is out of scope for every branch and PR; each PR ends at a reviewed, mergeable state.

**Binding-scope note:** longest-match command dispatch landed in v0.4.0 (commit `0b7cc23`), so the three-token `issue label add` / `issue label remove` names need no `internal/cli` work. Nothing in this release touches the dispatcher.

**Descope homes (from the release doc, each with a named boundary):**

- `repo view/edit` and any org/team surface stay out ("no consumer story yet"). Home: branch C's boundary allows exactly one repository-surface addition, the `HTMLURL` decode and `repo browse`; no repository view or edit command may appear on any branch. F records the deferral in the acceptance notes.
- Release create/upload/delete stays out ("no upload/create until someone actually asks"). Home: branch D's boundary forbids any release-authoring API method or command.

---

## Goals

1. `forge pr edit N [--title T] [--body B]` and `forge issue edit N [same]` patch title and body and print the updated object (`plans/releases/v0.4.2.md` §1).
2. `forge label list` and `forge issue label add|remove N --label NAME...` manage labels by name, resolved through the existing repository label list.
3. `forge pr browse N`, `forge issue browse N`, `forge repo browse` print the server-provided web URL, and open it in `$BROWSER` only with `--open`.
4. `forge release list | get TAG | download TAG [--asset NAME]` reads releases and lands assets in `.forge/cache/releases/` with pull-style receipts.
5. One version constant replaces the hard-coded string in `cmd/forge/main.go`; version numbers change in one place from now on.

## Success criteria

- Acceptance battery passes at every commit: `go vet ./...`, `gofmt -l .` prints nothing, `go build ./...`, `go test ./...`. No third-party dependencies.
- `plans/releases/v0.4.2.md` §1 checklist is fully ticked at commit F2, with acceptance notes in the v0.3.1 style. Each §1 box maps to one branch: edit to A, labels to B, browse to C, releases to D, version constant to E.
- `pr edit` and `issue edit` reject an invocation with no non-empty `--title`/`--body` before any HTTP request; valid calls send only the supplied fields and print the updated object.
- `label list` returns JSON when piped and a fixed table on a TTY. Label mutations resolve names once, preserve input order, stop on the first failed removal, and print a receipt only after success.
- Browse prints the server's `html_url` as plain text; `--open` is the only trigger for a browser, never a shell, and the URL still prints when opening.
- `release list` follows the shared paginator with table defaults; `release get TAG` uses the tag endpoint; `release download TAG` writes exact asset names through `store.WriteFile`, overwrites per filename, rejects an asset URL on a different host before the token is sent, and prints a receipt with each written path and byte count.
- The seeded `releases` savedir is `.forge/cache/releases`; `cache path` and `cache flush` include it automatically.
- `forge version` prints `forge-cli v0.4.2` from the constant, verified in F2's binary battery.

All five code branches can start in parallel off the v0.4.1 baseline; none gates on another. The merge order above serializes them.

Shared seams:

- Registration seam. Branches A and C add to `PRCommands()`/`IssueCommands()`; B adds `LabelCommands()`, C adds `RepoCommands()`, D adds `ReleaseCommands()`, E edits `versionCmd` in `cmd/forge/main.go`. The seam is the existing `cli.Command`/`Registry` contract (`plans/implementation/archive/v0.3.1.md`): each branch appends its own registrations and touches nothing else's. Whoever lands second rebases.
- `internal/api/issues.go` is touched by A1 (edit PATCH) and B1 (label methods) in independent blocks; A lands first, B rebases.
- `internal/api/types.go` is touched by C1 (`Repository.HTMLURL`) and D1 (release types) in independent blocks.
- `internal/cmds/views.go` receives each branch's own column set and row builder; no shared edits.
- The savedir seam is internal to D: D3 refactors `pull.go` and `pr_diff.go` onto one helper, and no other branch touches those files.

F is docs only. A failed acceptance check goes back to the owning branch; F never absorbs a late code fix.

## Branches

### Branch A, edit verbs

Purpose: partial title/body edits for pull requests and issues, riding the existing PATCH helpers. Position: first branch of PR 1; gates nothing. Touch boundary: `internal/api/pulls.go`, `internal/api/issues.go`, `internal/api/pulls_test.go`, `internal/api/issues_test.go`, new `internal/cmds/edit.go`, `internal/cmds/pr.go`, `internal/cmds/issues.go` (registration only), new `internal/cmds/edit_test.go`. Forbids: edit fields for state, draft, labels, assignees, or milestones; clearing a field with an empty value; a second GET around the PATCH; table output.

Commits:

1. `feat(api): PR and issue edit PATCH methods`: typed edit inputs with omitempty fields, `EditPullRequest` through the existing `patchPull`, `EditIssue` through a new shared `patchIssue` that `SetIssueState` also delegates to. Exact request/response tests; the refactored state call still sends the same body.
2. `feat(pr,issue): edit commands`: one parameterized command for both kinds, following the `prStateCmd`/`pullCmd` pattern. Rejects a missing or empty flag set with a usage error before any request, sends only the supplied fields, prints the updated object as JSON. Implementation and tests land together.

### Branch B, labels

Purpose: list repository labels and add or remove labels on an issue or issue-backed PR by name. Position: second branch of PR 1; B1 rebases onto A1 for `issues.go`, B2 gates B3 (the commands consume the resolver). Touch boundary: `internal/api/issues.go`, `internal/api/issues_test.go`, new `internal/cmds/labels.go`, `internal/cmds/issues.go`, `internal/cmds/views.go`, `cmd/forge/main.go`, new `internal/cmds/labels_test.go`. Forbids: label creation, deletion, or renaming; case-insensitive matching; a `pr label` spelling; one request per name during resolution.

Commits:

1. `feat(api): issue label add/remove methods`: POST/DELETE on the issue label collection, ids as int64 across the API package; `ListLabels` unchanged. Exact request and error tests.
2. `refactor(cmds): shared label-name resolution`: the issue-create name-to-id loop becomes the one resolver in the command layer; exact-match semantics, input order, duplicates, and the unknown-name error contract preserved. Behaviour-unchanged tests prove it.
3. `feat(label): label list and issue label mutations`: `label list` with table default (NAME/COLOR/ID), `issue label add` sending one POST with all resolved ids, `issue label remove` deleting per id in input order and stopping on the first failure, receipts printed only after success. Three-token names ride the existing longest-match dispatch.

### Branch C, browse

Purpose: print, or explicitly open, the web URL the server already returns. Position: first branch of PR 2; gates nothing. Touch boundary: `internal/api/types.go`, `internal/api/repo_test.go`, new `internal/cmds/browse.go`, `internal/cmds/pr.go`, `internal/cmds/issues.go` (registration only), `cmd/forge/main.go`, new `internal/cmds/browse_test.go`. Forbids: URL construction from host config (the server is the source), auto-opening, shell evaluation, a second API request, any repository view/edit command.

Commits:

1. `feat(api): repository web URL`: `HTMLURL` decodes on `Repository`, which stays a subset of the server schema; PR and issue payloads already carry it. Fixture test proves the decode.
2. `feat(pr,issue,repo): browse commands`: one parameterized command with three lookups; prints the URL line, then execs `$BROWSER` (whitespace-split, URL as final argument, no shell) only when `--open` is present. Implementation and tests land together, including the no-launch-without-flag and launch-failure cases.

### Branch D, releases

Purpose: read releases and download assets into the repository cache. Position: second branch of PR 2; D1 gates D2 and D5; D2 and D3 gate D6; D4 gates D6's default location. Touch boundary: new `internal/api/releases.go`, `internal/api/types.go`, `internal/api/client.go` and its test, `internal/config/config.go` and its test, new `internal/cmds/savedir.go`, `internal/cmds/pull.go`, `internal/cmds/pr_diff.go`, `internal/cmds/cache.go`, new `internal/cmds/releases.go`, `internal/cmds/views.go`, `internal/cli/help.go` (release family summary only), `cmd/forge/main.go`, new `internal/cmds/releases_test.go`. Forbids: release authoring or upload, client-side sorting or filters, a second filesystem writer, parallel downloads or retries, a `--dir` flag on download.

Commits:

1. `feat(api): release list and get`: typed `Release`/`ReleaseAsset` shapes, list through the shared `List` paginator, get by URL-escaped tag. Exact path, pagination, and error tests.
2. `feat(api): same-host asset download`: the raw transport seam accepts absolute URLs instead of only `/api/v1` paths, and `Download` validates scheme and host before anything is sent, so the token never reaches another host. Off-host, binary-body, APIError, and network-tag tests.
3. `refactor(cmds): one savedir resolution helper`: the duplicated directory-resolution blocks in `pull` and `pr diff` move into one helper pair; flag-then-config precedence and all error messages unchanged.
4. `feat(config): seed the releases savedir`: `.forge/cache/releases` enters the seeded savedir map, so `cache path` and `cache flush` cover it immediately; flush wording changes from cached JSON files to cached files because assets are binary.
5. `feat(release): list and get commands`: table-default list (TAG/NAME/DRAFT/PRERELEASE/PUBLISHED, server order), JSON-only get by tag; the `release` family page becomes real once download registers.
6. `feat(release): asset download with receipt`: exact asset names written through `store.WriteFile`, overwriting per filename, one receipt printed only after every selected asset succeeds; a mid-batch failure leaves earlier files in place and prints no receipt. Implementation and tests land together.

### Branch E, version constant

Purpose: the version string lives in one place and `forge version` reads it. Position: independent of everything; merges last, in PR 3, because nothing gates on it. Touch boundary: new `version.go` at the repo root, `cmd/forge/main.go`, a small test for the version command. Forbids: any other consumer or formatting change.

Commits:

1. `feat: single version constant`: repo-root `version.go` (package `forge`, exported constant), `forge version` prints it, introduced at `0.4.2`. This is the release-doc convention in action: the first commit of each release is the only place the number changes.

### Branch F, docs and acceptance

Purpose: record shipped behaviour and close the checklist. Position: last branch of PR 3; F1 gates on A-D, F2 on F1. Touch boundary: `README.md` and `plans/releases/v0.4.2.md`, nothing else.

Commits:

1. `docs(readme): v0.4.2 object management verbs`: document edit, labels, browse, releases, and the version constant in their existing sections; link the release doc for scope decisions instead of restating them.
2. `docs(plans): tick v0.4.2 checklist and record acceptance`: tick every §1 box and append acceptance notes in the v0.3.1 style, including the binary battery (`forge version` prints `forge-cli v0.4.2`, every new `-h` page exits 0) and the two live-instance gaps: real release payloads with asset redirects, and an actual browser launch.

## PR grouping and merge order

**PR 1: `edit and label verbs: PATCH title and body, manage labels by name`**. Branches A then B, five commits. One theme: write verbs on the PR/issue objects, with the shared name resolution built before the commands that use it. Self-contained: A touches the edit path, B the label path; the only overlap is one API file and registrations. Merges first.

**PR 2: `browse and releases: server URLs, release payloads, and asset downloads`**. Branches C then D, eight commits. One theme: verbs that read and retrieve; browse prints server-provided URLs, releases fetch payloads and land asset bytes. Depends on PR 1 only through merge-adjacent files (registrations, `types.go`, `views.go`); D rebases onto PR 1's result before the PR opens. Within the PR, C is independent and D's commits read in dependency order D1 through D6.

**PR 3: `version constant and v0.4.2 release close`**. Branches E then F, three commits. One theme: the binary, the tag, and the docs agree. Depends on PRs 1 and 2: F documents shipped behaviour and E's acceptance run covers every new command. E itself is independent and could merge earlier; it rides the closing PR because nothing waits on it.

Merge order: PR 1, PR 2, PR 3. Merging to main remains out of scope; the release doc records where each PR ends.

## Foundational contracts

Review anchor: read these shapes, then check the code against them. Signatures and doc comments only.

```go
// version.go, repo root. The only place a version number changes.
package forge

// Version is the forge-cli version. The first commit of each release bumps
// exactly this line; forge version is its only consumer.
const Version = "0.4.2"
```

```go
// internal/api/pulls.go and issues.go. Edit verbs ride the shared PATCH
// helpers; zero-value fields are omitted from the wire, and the command
// layer validates that at least one field is set before any request.
type EditPullInput struct {
	Title string `json:"title,omitempty"`
	Body  string `json:"body,omitempty"`
}

type EditIssueInput struct {
	Title string `json:"title,omitempty"`
	Body  string `json:"body,omitempty"`
}

// EditPullRequest patches title/body and returns the updated pull request.
func (c *Client) EditPullRequest(owner, repo string, index int, in EditPullInput) (*PullRequest, error)

// EditIssue patches title/body and returns the updated issue.
func (c *Client) EditIssue(owner, repo string, index int, in EditIssueInput) (*Issue, error)

// patchIssue is the shared PATCH implementation for issue fields;
// SetIssueState delegates here and keeps its signature.
func (c *Client) patchIssue(owner, repo string, index int, fields any) (*Issue, error)
```

```go
// internal/api/issues.go. Label ids are int64 everywhere, including
// CreateIssueInput.Labels.
type LabelIDsInput struct {
	Labels []int64 `json:"labels"`
}

// AddLabels adds labels by repository label id and returns the server's
// label payload for the issue.
func (c *Client) AddLabels(owner, repo string, index int, ids []int64) ([]Label, error)

// RemoveLabel removes one label by id. Success has no body.
func (c *Client) RemoveLabel(owner, repo string, index int, id int64) error
```

```go
// internal/cmds/labels.go. The only name-to-id path in the command layer.
// collectLabelNames returns repeated --label values in command-line order.
// resolveLabelIDs fetches repository labels once and maps exact names to
// ids, preserving input order and duplicates; unknown names are a runtime
// error listing them in input order.
func collectLabelNames(args []string, cmdName string) ([]string, error)
func resolveLabelIDs(ctx *cli.Ctx, names []string) ([]int64, error)

// LabelReceipt records the names the user asked for, in the same order,
// not the server's label payloads.
type LabelReceipt struct {
	Index  int64    `json:"index"`
	Action string   `json:"action"`
	Labels []string `json:"labels"`
}
```

```go
// internal/api/types.go. Repository gains one field; it stays a subset of
// the server schema. PR and Issue already carry HTMLURL.
type Repository struct {
	// existing fields unchanged
	HTMLURL string `json:"html_url"`

```

```go
// internal/cmds/browse.go. One parameterized command, three lookups;
// launching is its own function so browser policy has one home.
type browseCmd struct{ kind string } // "pr", "issue", or "repo"

// openInBrowser splits non-empty $BROWSER on whitespace, appends url as the
// final argument, and execs it directly. It never invokes a shell and
// routes child output to ctx.Stderr. A missing browser or non-zero exit is
// a runtime error.
func openInBrowser(url string, ctx *cli.Ctx) error
```

```go
// internal/api/types.go and releases.go. Typed release shapes; commands
// never decode releases into maps.
type Release struct {
	ID          int64          `json:"id"`
	TagName     string         `json:"tag_name"`
	Name        string         `json:"name"`
	Body        string         `json:"body"`
	Draft       bool           `json:"draft"`
	Prerelease  bool           `json:"prerelease"`

	HTMLURL     string         `json:"html_url"`

	ID                 int64  `json:"id"`
	Name               string `json:"name"`
	Size               int64  `json:"size"`

// ListReleases returns every repository release in server order, following

func (c *Client) ListReleases(owner, repo string) ([]Release, error)

// GetRelease fetches one release by tag; the tag is URL-path escaped.
func (c *Client) GetRelease(owner, repo, tag string) (*Release, error)
```

```go
// internal/api/client.go. The raw transport seam accepts absolute URLs, so
// DoRaw keeps building /api/v1 paths while Download fetches assets from the
// server's own download URLs. One seam: auth, timeout, logging, APIError
// conversion, network tagging.
func (c *Client) DoRaw(method, path string, query url.Values, body []byte) (*RawResponse, error) // unchanged signature

// Download fetches an absolute asset URL with the client's token and returns
// its bytes. The URL must match the API base host and port; the check runs

func (c *Client) Download(assetURL string) ([]byte, error)
```

```go
// internal/cmds/savedir.go. The one savedir resolution path; pull and

func resolveConfiguredSavedir(ctx *cli.Ctx, key string) (string, error)
```

```go
// internal/cmds/releases.go. Per-file rows, printed once, only after every
// selected asset succeeds. Files is non-nil, so an asset-less release
// serializes as "files": [].

	Name  string `json:"name"`
	Path  string `json:"path"`

	Tag   string                `json:"tag"`

}
```

Contracts by staying unchanged: `patchPull` (`internal/api/pulls.go`), the generic `List[T]` paginator (`internal/api/pagination.go`), `store.WriteFile` and the `store` package as the only filesystem writer, and the `cli.Command`/`Registry` longest-match dispatch (`internal/cli`). The seeded savedir map gains the `"releases"` key; no existing key changes.

## Abstractions and what they absorb

- The parameterized edit command (`editCmd{kind}`) matches `prStateCmd` and `pullCmd`: validation, output, and help construction exist once. Absorbs: a new editable object (register a kind) and a shared change to edit validation or output.
- Typed edit inputs at the API boundary: a new editable field lands in one input struct and its flag scan, while state PATCH callers keep the same transport helper. Absorbs: new edit fields per object.
- The one label resolver: any future label-consuming command reuses exact-match semantics instead of copying the loop; changing unknown-name behaviour edits one place. Absorbs: new label-name commands, a change to matching rules.
- `openInBrowser` as its own function: browser policy (wrappers, extra arguments, error mapping) changes in one function while the three lookups stay boring. Absorbs: a browser-policy change, a new browseable object (one lookup).
- The savedir helper pair: a new cache-backed command supplies a config key instead of reproducing the resolution block; changing relative-path or precedence rules edits one place. Absorbs: new cached artifact kinds, a change to resolution precedence.
- `Download` on the shared raw seam: a future binary or asset endpoint reuses auth, timeout, logging, and error mapping without building requests in commands, and host policy lives in one check. Absorbs: new download surfaces, stricter or looser host rules.
- Typed release shapes and ask-shaped receipts (`LabelReceipt`, `ReleaseDownloadReceipt` record what the user requested, not server echoes): new release views read fields, and new actions extend receipts without touching API methods. Absorbs: new release views, new label or download actions.
- The version constant: a version bump is one line, and no consumer can drift from it. Absorbs: every future release.
