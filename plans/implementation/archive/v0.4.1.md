# Implementation plan, v0.4.1

## Context

**What exists:** after v0.3.1, `pr create-batch` (`internal/cmds/pr_batch.go`) opens PRs for glob-matched local branches in lexical order, dry-run by default, `--yes` posting sequentially with stop-on-first-failure receipts. The plan/receipt share one `BatchReceiptItem` type. `internal/gitctx` exposes four read-only helpers (`CommitSubject`, `UniqueCommitCount`, `LocalBranches`, `RemoteHead`) with a shared `git()` error contract.

**Areas touched:** `internal/gitctx/repo.go` (+ tests), `internal/cmds/pr_batch.go`, a new `internal/cmds/pr_batch_plan.go` (+ tests), `internal/cmds/pr_batch_test.go`, `README.md`, `plans/releases/v0.4.1.md`.

**Depends on:** `plans/releases/v0.4.1.md` is the authority for behaviour, root cause, and the poll/matcher parameters. `plans/PRD.md` §§5-10 covers precedence and the error/exit-code contract. `plans/implementation/archive/v0.3.1.md` supplies the fixture patterns and the acceptance-notes style. No `design/*` decisions exist; nothing in `plans/proposals/` is active for this release.

**Preconditions:** v0.3.1 and v0.4.0 are merged on main. Cut every branch from current main. Merging to main is out of scope for every branch and PR; each PR ends at a reviewed, mergeable state.

**Descope homes (from the release doc's Defer section, each with a named boundary):**

- Stacked-PR base inference stays out. Home: branch B must not change how a plan item's `Base` is set; every item carries the one resolved base, and B's boundary forbids touching `ResolveCreateDefaults`.
- Dry-run duplicate preflight via the PR search endpoint stays out. Home: branch C's boundary forbids any preflight probing; duplicate detection is POST-time only.

---

## Goals

1. `create-batch` plans branches oldest tip first, with ancestry then lexical order breaking same-second ties, so stack parents post before their supersets (`plans/releases/v0.4.1.md` §1, ordering bullet).
2. Branches already contained in the resolved base are skipped before any POST and reported on stderr like the existing no-subject skip.
3. The `--yes` loop waits for each PR page to become reachable before the next POST, and a duplicate-PR server response is a skip, not a batch failure.

## Success criteria

- Acceptance battery passes at every commit: `go vet ./...`, `gofmt -l .` prints nothing, `go build ./...`, `go test ./...`. No third-party dependencies.
- `plans/releases/v0.4.1.md` §1 checklist is fully ticked at commit D2, with acceptance notes in the v0.3.1 style.
- Ordering, containment skips, all-skipped exit 2, unauthenticated probe, and duplicate-skip behaviour are each covered by a unit suite named under the branch that introduces them. Two behaviours are unverifiable without the live instance and are flagged in the acceptance notes: the exact duplicate-PR server wording (the matcher is provisional by design) and the page-wait note on a private repo.
- `BatchReceiptItem` gains no fields: skipped branches appear as stderr notes, never as dry-run items, and carry only `Error` in `--yes` receipts.

Shared seam: branches B and C both edit `createBatchCmd.Run` in `internal/cmds/pr_batch.go`, B in the plan-building block, C in the POST loop. The seam is the split the foundational contracts pin: B's branch codes against `planBatchBranches` and never touches the POST loop; C's branch codes against `pollPRPage` and `looksLikeDuplicatePR` and never touches plan building. Whoever lands second rebases; neither branch edits the other's hunks. Recommended integration order is B then C, so C's loop tests run against ordered plans.

D is docs only. A failed acceptance check goes back to the owning branch; D never absorbs a late code fix.

## Foundational contracts

Review anchor: read these shapes, then check the code against them. Signatures and doc comments only.

```go
// internal/gitctx/repo.go, beside the existing four helpers.

// BranchTipDate returns the branch tip's committer date as unix seconds
// (the age lazygit shows). Returns 0 when ref does not resolve; callers
// treat 0 as oldest.
func BranchTipDate(root, ref string) int64

// IsAncestor reports whether git considers ancestor an ancestor of ref.
// Equal refs count as ancestors, git's convention. Exit 1 means "not an
// ancestor", not an error; other failures return the gitctx error contract
// ("not inside a git repository", or "git merge-base: <stderr>").
func IsAncestor(root, ancestor, ref string) (bool, error)
```

```go
// internal/cmds/pr_batch_plan.go, the only owner of ordering and skips.

// planBatchBranches turns matched branch names into the ordered create-batch
// plan. Skip reasons become notes; the caller owns where notes go. Ordering:
// tip date ascending, ancestry breaks ties (parent first), then lexical.
// Every git lookup degrades to a default (0 date, "" subject, ancestry
// false), so there is no error return; an unresolvable base leaves the
// containment check inconclusive and the branch in the plan.
func planBatchBranches(root string, matched []string, base string) (items []BatchReceiptItem, notes []string)
```

```go
// internal/cmds/pr_batch.go, the POST loop's two knobs.

// pollPRPage GETs url up to attempts times, delay apart, without decoding
// the body or sending credentials. Reports whether any response had a
// status below 400; transport errors count as not-ready.
func pollPRPage(client *http.Client, url string, attempts int, delay time.Duration) bool

// looksLikeDuplicatePR reports whether a server error message indicates the
// batch PR already exists for that head branch. Provisional: refine this
// matcher and its test together when the live Forgejo wording is confirmed.
func looksLikeDuplicatePR(msg string) bool
```

`BatchReceiptItem` (`internal/cmds/pr_batch.go`) is a contract by staying unchanged: same type for plan and receipt, no new fields. Skipped branches never appear as dry-run items and carry only `Error` in `--yes` receipts.

## Abstractions and what they absorb

- `planBatchBranches`: a new skip reason or a changed ordering rule edits one function; dry-run, `--yes`, and the receipt contract stay untouched. Absorbs: new skip reasons, new ordering keys.
- The gitctx helper set: a new branch fact (upstream tracking, author date) lands as one helper beside the existing four, not as a new shell-out inside cmds. Absorbs: any new per-branch git fact.
- `looksLikeDuplicatePR`: confirmed Forgejo wording or a stricter matcher changes one function and its test together. Absorbs: the move from provisional substring to verified matching.
- `pollPRPage` taking a client: a different readiness probe (authed API check, JSON decode) replaces one function without touching the POST loop, and the client is the single knob for auth and timeout. Absorbs: a probe redesign, per-repo probe tuning.
- `BatchReceiptItem` unchanged: stdout consumers never see a shape change. Absorbs: every new skip or wait behaviour, which reports through stderr notes instead of new fields.
