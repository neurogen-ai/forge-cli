# Implementation plan — v0.1.3

## Context

- **What exists:** forge-cli v0.1.2 works end to end. `cli.Run` (`internal/cli/cli.go`) dispatches flat registry paths ("pr create") and prints one generic top-level usage line; commands validate their own args and return `cli.Error` with `ExitUsage` on bad input, which `reportError` prints as a bare message. There is no per-command help and no way to discover subcommands short of reading the README. Behavior spec in `plans/releases/v0.1.3.md`.
- **Files touched:** `internal/cli/cli.go`, `internal/cli/help.go` (new), `internal/cli/help_test.go` (new), `internal/cli/cli_test.go`, `internal/cmds/pr.go`, `internal/cmds/issues.go`, `internal/cmds/save.go`, `internal/cmds/cache.go`, plus one `_test.go` per cmds file where noted, `cmd/forge/main.go`, `README.md`.
- **Depends on:** `plans/releases/v0.1.3.md` (behavior authority). The Command interface and Ctx live in `internal/cli/registry.go`; exit codes in `internal/cli/exit.go`.

## Goals

1. `-h` / `--help` works at every level: `forge -h`, `forge pr -h`, `forge pr create -h`.
2. Top-level usage lists command families first ("basic commands"), each pointing at its own `-h` page.
3. Every usage-failure branch prints the most relevant help available. Fail-branch table (decided, do not deviate):

| Fail branch in `cli.Run` | Help printed |
|---|---|
| unknown/bad leading global flag (`forge --bogus pr list`) | top-level Usage |
| missing value / bad `--timeout` AFTER command resolved (`forge pr list --token`) | resolved command's page |
| command raises `ExitUsage` (`forge pr get abc`) | that command's page |
| unknown command matching no family | top-level Usage |

`reportError` stays command-blind; branches that know the resolved command print its page at their own site.

## Success criteria

- All acceptance criteria of `releases/v0.1.3.md` pass.
- Adding a new command updates top-level and group help automatically; only the new command's own file changes (plus one summary entry when it starts a new family).
- `go vet ./...` and `go test ./...` clean; existing tests unmodified except where this plan says so.

## Abstractions

- **`cli.Documented` optional interface** (`HelpPage() string`) with a synthesized fallback from `Name()`+`Summary()`: a command without a hand-written page still gets usable help, and writing richer help touches only that command's file. Absorbs any future per-command documentation need (examples, see-also lines).
- **Groups derived from registered names**, not declared separately: any first token shared by two or more commands becomes a family with an auto-built `-h` page. Adding `forge label list` later creates the `label` family with zero edits to help code; only a one-line summary for the new prefix goes into the `groupSummary` map.
- **Help printed by `cli.Run`, not by commands**: commands never parse `-h` themselves and never print their own errors' help, so the fail-branch table in Goals is enforced in one place for every current and future command.

# Branch A — cli help core

### Step A1: internal/cli/help.go + Run wiring

Create `internal/cli/help.go`. Contracts:

```go
package cli

// Documented is implemented by commands with a hand-written help page.
// The page's FIRST LINE MUST BE the synopsis: "use: forge <name> [flags] [args]".
type Documented interface {
	HelpPage() string
}

// HelpText returns the command's help page. Fallback for non-Documented
// commands: "use: forge <name>\n\n<Summary()>".
func HelpText(c Command) string

// PrintHelp writes HelpText(c) followed by a newline.
func PrintHelp(w io.Writer, c Command)

// GroupPrefix returns the shared first token of cmd's name if two or more
// registered commands start with that token ("pr" for all pr_* commands),
// else false. Single-command names ("version") return false.
func (r *Registry) GroupPrefix(name string) (prefix string, ok bool)

// PrintGroupPage writes the family help page:
//
//	use: forge <prefix> <subcommand> [args]
//
//	<groupSummary[prefix]>            // OMIT the whole line (and one blank line)
//	                                  // when the map has no entry or an empty value;
//	                                  // tests use fake prefixes so they exercise omission
//
//	  <subcommand name padded>  <Summary()>
//	  ...
//
//	run `forge <prefix> <subcommand> -h` for details
// Subcommand lines come from Registry.Sorted(), filtered to the prefix,
// showing only the part after the prefix.
func (r *Registry) PrintGroupPage(w io.Writer, prefix string)

// INTENDED behavior, do not "fix": grouping derives from registry contents at
// call time. A second command later registering under an existing single word
// (say "version bump") re-renders that word as a family automatically. That
// is the absorption property working, not a bug.

// groupSummary maps a family prefix to the one-line description shown on its
// group page and in top-level usage. New families add one entry here.
var groupSummary = map[string]string{
	"pr":    "pull requests",
	"issue": "issues",
	"save":  "fetch data and write it to disk",
	"cache": "local savedir maintenance",
}
```

Rewrite `Usage(w io.Writer, reg *Registry)` in `internal/cli/cli.go` (keep the exported name and signature; `main.go` and `Run` already call it). New output, exactly:

```
usage: forge [--host H] [--owner O] [--repo R] [--token T] [--config P] [--timeout S] [-v] <command> [args]

commands:
  cache                   local savedir maintenance  (forge cache -h)
  issue                   issues  (forge issue -h)
  pr                      pull requests  (forge pr -h)
  save                    fetch data and write it to disk  (forge save -h)
  version                 print the forge-cli version

run `forge <command> -h` for details
```

Rules for the commands block: iterate `reg.Sorted()`; emit a group line once per distinct `GroupPrefix`, then skip that prefix's other members; emit non-grouped commands normally. Padding is `%-24s` for the name column like today; after a padded group name comes the summary from `groupSummary`, two spaces, then `(forge <prefix> -h)`. Families sort alphabetically as a side effect of `Sorted()` taking each family's first member's position; accept that, do not special-case it.

Add `Help bool` to `Ctx` in `internal/cli/registry.go`, next to `Verbose`.

Change `Run` in `internal/cli/cli.go`:

1. In the leading-flag loop, treat `-h` and `--help` exactly like `-v`: set `ctx.Help = true`, consume, continue.
2. In the `i >= len(argv)` early return: if `ctx.Help`, print `Usage(ctx.Stdout, reg)` and return `ExitOK`; otherwise keep today's behavior (Usage to stderr, `ExitUsage`). Bare `forge` with no args never reaches `Run` (`main()` handles it); leave that split untouched.
3. `-h` wins and swallows everything after it. Immediately after the command resolves (including the two-token join), BEFORE `applyGlobalArgs` and BEFORE `Prepare`: if `ctx.Help` is true OR any remaining arg equals `-h` or `--help`, print the applicable page to STDOUT and return `ExitOK`. Following flags are ignored entirely (`forge pr create -h --title x` prints the create page, exits 0, makes no requests):
   - `cmd != nil` → `PrintHelp(ctx.Stdout, cmd)`
   - `cmd == nil` and `GroupPrefix(path)` succeeds → `reg.PrintGroupPage(ctx.Stdout, prefix)`
   - otherwise → `Usage(ctx.Stdout, reg)`
4. `applyGlobalArgs` additionally recognizes `-h`/`--help` and silently drops them (defense in depth; step 3 normally returns first). It must NEVER pass them to commands.
5. When the command path does not resolve but `GroupPrefix(path)` succeeds (bare `forge pr`): `reg.PrintGroupPage(ctx.Stdout, prefix)`, return `ExitOK`.
6. Fail-branch help, per the table in Goals:
   - The `applyGlobalArgs` error path (it only fires after a command resolved): print the command's page after the error, then return `ExitUsage`:
     ```go
     fmt.Fprintln(ctx.Stderr, err.Error())
     fmt.Fprintln(ctx.Stderr)
     PrintHelp(ctx.Stderr, cmd)
     ```
   - The unknown-command path stays unchanged (unknown message + `Usage` to stderr).
7. In the final error handling, after `reportError`:

```go
code := reportError(ctx.Stderr, err)
var cerr *Error
if errors.As(err, &cerr) && cerr.Code == ExitUsage {
	fmt.Fprintln(ctx.Stderr)
	PrintHelp(ctx.Stderr, cmd)
}
return code
```

Only `ExitUsage` triggers the page; runtime, auth, network, and context errors stay one-liners.

Do NOT:
- change how flags are parsed for commands beyond recognizing `-h`/`--help`,
- touch the bare-`forge` no-args path in `main.go`,
- make `reportError` aware of commands (keep the printing in `Run`),
- add a `forge help <cmd>` word-form (out of scope for this release),
- touch anything under `internal/cmds` or `internal/api`.

Tests, create `internal/cli/help_test.go` (registry with fake commands, bytes.Buffer writers):

1. Two commands "a list", "a get", one "b": `GroupPrefix("a list")` → `"a", true`; `GroupPrefix("b")` → false.
2. `HelpText` fallback: command not implementing `Documented` → `"use: forge b\n\nb summary\n"` shape (exact Summary text of the fake).
3. `PrintGroupPage` for "a" contains `use: forge a <subcommand>`, both member summaries, and the trailing hint line.
4. Rewritten `Usage` lists the "a" group line once, not per member, and lists "b" normally.

Extend `internal/cli/cli_test.go` end-to-end cases (existing harness):

5. `[]string{"pr", "-h"}` style invocation with a registered "x do" command: exit 0, stdout contains the x group page.
6. `{"x", "do", "-h"}`: exit 0 even though the command would fail without args; stdout starts `use: forge x do`; Prepare was never called (assert via sentinel).
7. `{"x", "do"}` where Run returns `&Error{Code: ExitUsage}`: exit 2, stderr contains the error message, a blank line, then the full help page.
8. Same command returning `Code: ExitRuntime`: exit 1, stderr has NO help page.
9. Bare `{"x"}` (group path, no -h): exit 0, group page on stdout.
10. Trailing `-h` swallowing later junk: `{"x", "do", "-h", "--title", "z"}` → exit 0, page on stdout, Prepare sentinel NOT called.
11. `{"-h"}` alone: exit 0, Usage on stdout (NOT stderr).
12. Post-resolution flag failure: registered command with args {"do", "--timeout", "x"} → exit 2; stderr has the error, a blank line, then the command's page.
13. Leading-flag failure: args {"--bogus", "x", "do"} → exit 2; stderr has the unknown-flag error AND top-level Usage, and NO command page.

Verify:

```
go test ./internal/cli/ && go vet ./...
```

Expected: new and existing cli tests pass. Full-suite cmds tests must still pass unchanged (they never pass -h).

# Branch B — help pages for every command

### Step B1: implement Documented across internal/cmds and version

Each command below gets a `HelpPage() string` method in its existing file. Copy these texts verbatim; they are decisions, not suggestions. Every page's first line is the `use:` synopsis.

In `internal/cmds/pr.go`, four methods:

```go
func (prCreateCmd) HelpPage() string { return `use: forge pr create --title T [--head B] [--base B] [--body TEXT]

Open a pull request. Head defaults to $FORGE_HEAD, then your current git
branch. Base defaults to $FORGE_BASE, then [defaults] base in config.

A 404 here is diagnosed: missing base branch, missing head branch, or pull
requests disabled for the repo.` }

func (prGetCmd) HelpPage() string { return `use: forge pr get N

Print one pull request as JSON. N is the PR number.` }

func (prListCmd) HelpPage() string { return `use: forge pr list [--state open|closed|all] [--page N] [--limit M]

List pull requests as a JSON array. Defaults: state open, page 1, no limit.` }

func (prConvCmd) HelpPage() string { return `use: forge pr conversation N [--format flat|grouped]

Print a PR's comments, reviews, and inline review comments as JSON.
--format grouped (default) nests review comments under their review;
--format flat merges everything into one created_at-sorted array with a
"kind" field per item.` }
```

[savedir] pr-conversation in config. Prints the written file path on stdout.`
}
