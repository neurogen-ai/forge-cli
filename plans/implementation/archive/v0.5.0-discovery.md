# Implementation plan, v0.5.0

## Context

v0.4.0 completes the typed write loop and introduces `api.Client.DoRaw` for raw text responses. The CLI already has global format flags, table renderers, paginated `api.List`, repository-aware wiring, and git helpers for the current branch. It still lacks a safe API passthrough, server-side discovery, and the one-shot status value a Starship caller can poll.

This plan is the companion split from `plans/implementation/v0.4.0.md`. It covers generic discovery only. The former one-line auto-sync service idea remains deferred to v0.8.0.

Files touched:

- `internal/cli/registry.go`, `cmd/forge/main.go`
- `internal/cmds/cmds.go`, `internal/cmds/rawapi.go` (new), `internal/cmds/search.go` (new), `internal/cmds/pr_sync.go` (new), `internal/cmds/pr.go`
- `internal/api/search.go` (new), `internal/api/pulls.go`
- `internal/gitctx/repo.go`
- API, CLI, command, and gitctx tests beside those packages
- `README.md`, `plans/releases/v0.5.0.md`, and `plans/releases/v0.8.0.md`

This plan depends on `plans/releases/v0.5.0.md` after the v0.4.0 release-boundary update, `plans/PRD.md` §§5-10, `plans/implementation/v0.4.0.md` Branch C1, `plans/implementation/archive/v0.3.0.md`, `plans/implementation/archive/v0.3.1.md`, `plans/proposals/v0.3.0-extension.md`, and the existing README. Merging to `main` is out of scope.

## Goals

1. Let agents call any configured Forgejo API path without reaching for curl, while keeping authentication, URL construction, request logging, and error mapping inside forge-cli.
2. Add repository-scoped issue and PR search with the existing paginated list helper and table/JSON output contract.
3. Add a one-shot `pr sync-status` value for Starship or another caller to poll. The command compares the local branch head with the head SHA of its open PR and never starts a daemon.
4. Keep the command core stable as query parameters, API response types, and callers grow. Input parsing belongs at the CLI boundary; transport and search query construction belong in named API modules.

## Success criteria

- `forge api repos/{owner}/{repo}/swagger.v1.json` sends one authenticated GET below `/api/v1` and writes a valid JSON response. A text response is passed through without JSON formatting.
- `forge api` accepts a leading or non-leading slash, repeatable `--q k=v`, `--method`, and `--input @file|JSON|-`. `--input -` reads only the configured `Ctx.Stdin` reader.
- `--jq` invokes the system `jq` binary without a shell. Missing `jq` exits 2 with an install hint; a failed filter exits 1 and preserves jq's stderr.
- `forge search issues QUERY` and `forge search prs QUERY` send the right `owner`, `repo`, `q`, `type`, and optional `state` query values, follow `Link` pagination, and use existing issue-shaped JSON/table rows.
- `forge pr sync-status [BRANCH]` returns `in-sync`, `out-of-sync`, or `no-pr` without treating an out-of-sync result as an error. The Starship caller owns polling.
- `go test ./...`, `go vet ./...`, `go build ./...`, and `gofmt -l .` all pass without adding a Go dependency.

## Tests

Use `httptest` for API and command requests. API passthrough tests capture method, path, query, request bytes, authorization, content type, and response content type. CLI tests substitute `Ctx.Stdin` with `strings.NewReader` and use a temporary executable named `jq` so the suite does not depend on a host installation. Search tests serve two pages with a `Link` header. Sync tests use the existing temporary git repository helpers and an `httptest` server.

A manual Starship smoke may invoke the compiled command repeatedly in a disposable checkout, but no service, prompt configuration, or live credential is required by the automated suite.

## Binding decisions

D1. `forge api` is a raw authenticated caller below the configured `/api/v1` base. It accepts exactly one path, defaults to GET, accepts any valid HTTP method token, and uses `--q` for query values. It never constructs a URL outside the configured host.

D2. Request input is one of a literal byte string, `@file` read relative to the process working directory, or `-` read from `Ctx.Stdin`. The command does not parse or rewrite the request JSON before sending it. A non-nil input body uses `application/json` through `DoRaw`.

D3. A response with a media type containing `json` or ending in `+json` is validated as JSON. Without `--jq`, the command writes that decoded value with the existing two-space `writeJSON` format. Other media types are written byte-for-byte. An empty successful body produces no output.

D4. `--jq` invokes the `jq` executable from `PATH` with the filter as one argument. Forge-cli does not implement jq and does not add a Go jq dependency. Missing `jq` is a usage error; a jq process that returns non-zero is a runtime error.

D5. Search results use `api.Issue` for both `type=issues` and `type=pulls`, because Forgejo returns issue-shaped objects for this endpoint. Both commands reuse `issueListColumns` and `issueListRows`. A later PR-specific search view changes one renderer decision, not the search transport.

D6. `pr sync-status` is one request sequence per invocation. It compares `git rev-parse --verify refs/heads/{branch}` with the matching open PR's `Head.Sha`. Polling belongs to Starship or another caller. The CLI does not require `.forge/` to exist and does not run a background process.

D7. Sync states are `in-sync`, `out-of-sync`, and `no-pr`. All three are successful reports with exit 0. Context, git, network, auth, and API failures retain their existing non-zero exit codes.

// Stdin is the process input used by commands such as forge api --input -.

### Step F2: implement passthrough requests without jq

Create `internal/cmds/rawapi.go`:

```go
type apiCmd struct{}

func (apiCmd) Name() string      // "api"
func (apiCmd) Summary() string
func (apiCmd) RequiresAPI() bool // true
func (apiCmd) Run(args []string, ctx *cli.Ctx) error
```

The command must:

1. Remove the value-bearing `--method`, `--input`, `--jq`, and repeatable `--q` flags from the positional view and require exactly one path. Empty or multiple paths return `ExitUsage`.
2. Trim one leading `/` from the path, then pass `"/" + path` to `ctx.API.DoRaw`. This makes `repos/o/r/issues` and `/repos/o/r/issues` equivalent while keeping the client responsible for `/api/v1`.
3. Default method to `GET`. Uppercase a supplied method and reject an empty or invalid HTTP method token with `ExitUsage`; do not use an allowlist because passthrough must support PATCH, DELETE, and future methods.
4. Parse every `--q` value with `strings.Cut(value, "=")`. Reject a missing or empty key with `ExitUsage`; allow an empty value and use `url.Values.Add`.
5. Resolve `--input` once. `-` reads all of `ctx.Stdin`; a leading `@` reads the named file with `os.ReadFile`; every other value is sent as its literal UTF-8 bytes. Read errors are `ExitUsage` with the filename in the hint.
6. Reject `--jq` with `ExitUsage` in this step. Step F3 replaces that temporary branch with the jq implementation without changing request behavior.
7. Call `ctx.API.DoRaw(method, "/"+path, query, body)`, map errors with `mapErr`, and render the successful body according to D3. Put media-type detection and JSON rendering in named helpers in `rawapi.go`:

```go
func isJSONMediaType(contentType string) bool
func writeAPIResponse(w io.Writer, contentType string, body []byte) error
```

`writeAPIResponse` must treat `application/json`, parameters such as `application/json; charset=utf-8`, and `application/problem+json` as JSON. Decode into `any` with `encoding/json`, then call the existing `writeJSON`. For a non-JSON response, call `w.Write(body)` without adding bytes. For an empty body, return nil.

Register `apiCmd{}` directly in `cmd/forge/main.go` with the other top-level commands. Give it a help page that documents the auth caveat: it sends the configured token to every path requested under the configured host, so agents must not pass untrusted paths.

Add `internal/cmds/rawapi_test.go` with:

- exact GET path and authorization capture;
- optional leading slash equivalence;
- method and repeated query values;
- inline JSON, `@file`, and stdin request bodies;
- JSON response validation and formatting;
- non-JSON byte preservation;
- missing path, multiple path, malformed query, unreadable file, nil stdin, and temporary `--jq` usage errors;
- mapped API errors.

Do not:

- allow arbitrary absolute URLs or a second host flag;
- follow redirects manually or expose response headers;
- add multipart, binary request, or upload flags;
- invoke a shell to run the request or filter;
- pretty-print text responses.

Verify:

```sh
go test ./internal/cmds/ ./internal/api/ ./internal/cli/
go build ./...
```

Expected result: passthrough tests see the exact request and response contracts, and the binary builds with `forge api` registered.

### Step F3: add the jq filter

In `internal/cmds/rawapi.go`, replace the temporary `--jq` usage error with:

```go
func runJQ(out, errOut io.Writer, filter string, body []byte) error
```

Use `exec.Command("jq", filter)` with `bytes.NewReader(body)` as stdin, `out` as stdout, and `errOut` as stderr. Pass the filter as one argument. Do not use `sh -c` or interpolate it into a command string.

Map process errors as follows:

- If the executable cannot be found, return `*cli.Error{Code: cli.ExitUsage, ...}` with a hint to install `jq` or omit `--jq`.
- If jq starts and exits non-zero, return `ExitRuntime` and keep jq's stderr available to the user. Include the filter-process failure in the structured error without replacing jq's diagnostic with a generic success message.
- If jq succeeds, return nil and do not append another newline beyond jq's own output.

When `--jq` is present, call `runJQ` with the raw body before the ordinary JSON renderer. jq receives the body even when the server's content type is missing; its own parse error is the result for invalid input.

Test with fake executables in `internal/cmds/rawapi_test.go`: create a temporary `jq` script that records its first argument and emits a fixed result, prepend its directory to `PATH` with `t.Setenv`, and assert filter and output. Add a missing executable test with an empty temporary `PATH`, and a non-zero fake jq test that captures stderr and expects exit 1. Do not make the suite depend on the host jq installation.

Do not:

- implement a jq parser in Go;
- accept multiple `--jq` filters or compose filters locally;
- discard jq stderr;
- turn jq failures into successful API responses.

Verify:

```sh
go test ./internal/cmds/ -run 'Test.*(API|JQ|Jq)'
go vet ./...
```

Expected result: fake-jq success, missing-binary, and filter-failure tests pass, and vet is clean.

### Step I2: implement `pr sync-status`

Create `internal/cmds/pr_sync.go`:

```go
type prSyncStatusCmd struct{}

func (prSyncStatusCmd) Name() string      // "pr sync-status"
func (prSyncStatusCmd) Summary() string
func (prSyncStatusCmd) RequiresAPI() bool // true

// SyncStatusReceipt is a one-shot report for prompt integrations.
type SyncStatusReceipt struct {
	Branch    string `json:"branch"`
	PR        *int64 `json:"pr,omitempty"`
	LocalSHA  string `json:"local_sha"`
	RemoteSHA string `json:"remote_sha,omitempty"`
	State     string `json:"state"` // in-sync, out-of-sync, or no-pr
}

func (prSyncStatusCmd) Run(args []string, ctx *cli.Ctx) error
```

`Run` must require `ctx.Repo`, accept zero or one branch argument, use `gitctx.CurrentBranch(ctx.Repo.Root)` when omitted, and return `ExitUsage` for extra arguments or `ExitContext` for detached HEAD or a missing local branch. Use `gitctx.HeadSHA` once and map git failures to `ExitContext` with the branch name.

Call `FindOpenPullRequestByHead` with the resolved branch. If no PR matches, print `SyncStatusReceipt{Branch: branch, LocalSHA: local, State: "no-pr"}` and exit 0. If a PR matches, set `PR` to a pointer containing its number, set `RemoteSHA` to `pr.Head.Sha`, and set `State` to `"in-sync"` only when the two non-empty SHAs are equal, otherwise `"out-of-sync"`. An empty server head SHA is an API data error: return `ExitRuntime` rather than claiming synchronization.

Always print the receipt with `writeJSON`. Do not implement `DefaultIsTable`; the status command is machine-readable and ignores no-pr/out-of-sync as failures. Register it through `PRCommands()` so the existing PR landing page index picks it up.

Create `internal/cmds/pr_sync_test.go` with temporary repositories and handlers for no PR, matching SHA, differing SHA, empty remote SHA, missing local branch, detached HEAD, extra argument, and API failure. Assert that the differing SHA path exits 0 and reports `state: "out-of-sync"`.

Do not:

- poll, sleep, watch, or start a service;
- require `.forge/` or write a cache file;
- return exit 1 just because the branch is out of sync;
- compare commit dates, titles, or diffs;
- open a browser or emit Starship escape sequences.

Verify:

```sh
go test ./internal/cmds/ ./internal/gitctx/ ./internal/api/
```

Expected result: all three report states are JSON, only genuine context/API failures are non-zero, and no file is written.

## Abstractions and future changes

- `DoRaw` from v0.4.0 remains the one transport seam for arbitrary response media types; a future binary download or webhook probe does not duplicate authentication and status handling.
- `Ctx.Stdin` keeps process input at the runtime boundary; a future command that consumes a stream can substitute it in tests without changing function signatures.
- `flagValues` gives repeatable flags one parser contract; future multi-value command options do not each invent their own argument scan.
- `writeAPIResponse` isolates media-type and JSON rendering; a future response format or pretty-print option changes one renderer rather than the request command.
- `runJQ` isolates the external filter process; a future supported filter tool can replace that adapter without changing path, input, or API error handling.
- `SearchIssueParams` owns the server query vocabulary; a future search filter adds one field and one query mapping without scattering URL construction across commands.
- Reusing `issueListRows` keeps search presentation tied to the existing issue shape; a future PR-specific table is one renderer decision rather than a second search transport.
- `FindOpenPullRequestByHead` keeps exhaustive list lookup in the API package; a future status comparison by another server-owned ref can reuse the same pagination and matching boundary.
- `HeadSHA` keeps git subprocesses in `internal/gitctx`; a future local ref comparison adds a helper there instead of shelling out from a command.
- `SyncStatusReceipt` separates report state from process failure; a future prompt integration can add a display field without making an ordinary out-of-sync report look like a transport error.
