# Implementation plan, v0.4.1

## Context

**What exists:** after v0.3.1, `pr create-batch` (`internal/cmds/pr_batch.go`) opens PRs for local branches matching a glob, dry-run by default, `--yes` to post with stop-on-first-failure receipts. The plan is built in lexical branch order and nothing checks whether a branch is already contained in the resolved base, so a merged superset branch (or a branch posted before its stack parent) leaves the remaining PRs empty. gitctx already exposes `CommitSubject`, `UniqueCommitCount`, `LocalBranches`, and `RemoteHead` (`internal/gitctx/repo.go`).

**Files touched:** `internal/gitctx/repo.go`, `internal/cmds/pr_batch.go`, `internal/cmds/pr_batch_plan.go` (new), plus tests `internal/gitctx/repo_test.go`, `internal/cmds/pr_batch_test.go`, `internal/cmds/pr_batch_plan_test.go` (new), `README.md`, `plans/releases/v0.4.1.md`.

**Depends on:** `plans/releases/v0.4.1.md` (the authority for behaviour and the root-cause analysis; this plan does not restate it), `plans/PRD.md` §§5–10 (precedence, exit codes, error contract), `plans/implementation/archive/v0.3.1.md` (fixture patterns and the acceptance-notes style Branch D reuses).

**Precondition:** v0.3.1 is merged and on main (it is). Cut every branch below from main. v0.4.1 is independent of the v0.4.0 write verbs; the only overlap with a concurrent v0.4.0 branch is `PRCommands()` in `internal/cmds/pr.go`, which v0.4.1 never edits. Merging to main is out of scope for every branch.

**Decisions this plan pins** (all trace to the release doc; kept here only as compile-time shapes):

- Branch ordering and skip logic live in one pure function, `planBatchBranches`; the `--yes` loop and the dry-run return never encode either.
- `BranchTipDate` reads the committer date (`--format=%ct`, equivalent to `%(committerdate:unix)`, which is what lazygit shows). It is the only branch-age key this release considers.
- `IsAncestor` uses `git merge-base --is-ancestor` with exit-code-aware handling; the shared `git()` helper cannot be reused because it maps any nonzero exit to an error.
- Containment preflight is local only (`UniqueCommitCount(base..branch) == 0`). A base that does not resolve locally (server-only name) makes the check inconclusive: the branch stays in the plan and the POST surfaces the real error.
- The page-availability probe is unauthenticated, body-undecoded, and bounded (5 attempts, 500 ms apart). Timeout prints a stderr note and never fails the batch.
- Duplicate-PR detection is a provisional substring matcher on the server message, recorded verbatim in the receipt item's `Error` field. Stop-on-first-failure still applies to every other failure class.

---

## Goals

1. `create-batch` plans branches oldest tip first, with ancestry then lexical order breaking same-second ties, so stack parents post before their supersets.
2. Branches already contained in the base never reach the POST; they are reported as `skipped: <branch> (already in base)` on stderr, like the existing no-subject skip.
3. `--yes` waits for each PR page to become reachable before posting the next, and treats a duplicate-PR server response as a skip instead of a batch failure.

## Success criteria

- A dry-run plan for a stack with identical committer dates lists the parent before the child; distinct dates order oldest first regardless of spelling.
- A branch whose tip is contained in the base, including the base branch itself when PATTERN matches it, is skipped with a stderr note and never appears in the plan or the receipt.
- All branches skipped (no subject or already in base) still exits 2, and the error message names both skip reasons.
- `--yes` polls the new PR's `HTMLURL` with no `Authorization` header, up to 5 times at 500 ms; a timeout prints `note: <branch> page not confirmed available before continuing` and the batch continues.
- A server response whose message contains `already exists` fills the item's `error` field verbatim, prints `skipped: <branch> (PR already exists)`, and lets the remaining branches post; other failures keep the stop-on-first-failure exit.
- `go vet ./...`, `gofmt -l .` (empty), `go build ./...`, and `go test ./...` pass at every verified step; no third-party dependencies.

## Tests

Inline per step; each step's Verify block names the commands to run. gitctx tests use the `requireGit`/`initRepo` fixtures in `internal/gitctx/repo_test.go`. cmds tests use `testCtx` (`internal/cmds/pr_test.go`) and the `batchRepo`/`batchPostServer` fixtures (`internal/cmds/pr_batch_test.go`), extended with a date-pinning fixture `batchRepoAt` (Step B1). Unit suites never require network. Two behaviours cannot be fully verified without the live instance and are flagged in the acceptance notes (Step D2): the exact duplicate-PR server wording, and the page-wait note on a private repo.

## Abstractions and what they absorb

- `planBatchBranches`: a new skip reason or a changed ordering rule edits one function; dry-run, `--yes`, and the receipt contract stay untouched.
- The gitctx helper set (`BranchTipDate`, `IsAncestor` beside the existing four): a new branch fact (upstream tracking, author date) lands as one helper, not a new shell-out inside cmds.
- `looksLikeDuplicatePR`: confirmed Forgejo wording or a stricter matcher changes one function and its test together.
- `pollPRPage`: a different readiness probe (an authed API check, a JSON decode) replaces one function without touching the POST loop; `pageProbeClient` is the single knob for auth and timeout.
- `BatchReceiptItem` stays unchanged: preflight skips stay in stderr notes, so the plan/receipt type that stdout consumers already parse never grows fields.

# Branch A, gitctx helpers

Pure `internal/gitctx` work. Gates Branch B.

### Step A1: `BranchTipDate` and `IsAncestor`

Append to `internal/gitctx/repo.go`, below `RemoteHead`:

```go
// BranchTipDate returns the branch tip's committer date as unix seconds
// (`git log -1 --format=%ct`, equivalent to %(committerdate:unix), the age
// lazygit shows). It returns 0 when ref does not resolve; callers treat 0
// as oldest.
func BranchTipDate(root, ref string) int64
```

Implementation: `git(root, "log", "-1", "--format=%ct", ref)`, parse with `strconv.ParseInt`, any failure returns 0. This mirrors `CommitSubject`'s degraded-error shape, so no error return is needed.

```go
// IsAncestor reports whether git considers ancestor an ancestor of ref
// (`git merge-base --is-ancestor`). Equal refs count as ancestors, which is
// git's convention; callers that need strict ancestry handle equality.
//
// Exit 1 means "not an ancestor", not an error, so this helper runs exec
// directly instead of going through git(), which maps any nonzero exit to
// an error.
func IsAncestor(root, ancestor, ref string) (bool, error)
```

Implementation: `exec.Command("git", "merge-base", "--is-ancestor", ancestor, ref)` with `cmd.Dir = root` and a captured stderr. Exit 0 returns `true, nil`. Exit 1 returns `false, nil`. Any other failure returns `false` plus an error whose text mirrors `git()`: `"not inside a git repository"` when stderr is empty or mentions `not a git repository`, otherwise `git merge-base: <stderr>`.

Extend `internal/gitctx/repo_test.go`:

1. `BranchTipDate` matches `git log -1 --format=%ct` output for a real branch.
2. A missing ref returns 0.
3. `IsAncestor` is true parent→child, false child→parent, true for the same ref twice, and errors on a missing ref.

Do not:

- add an author-date helper or a for-each-ref batch-date helper;
- touch any existing gitctx helper or any package outside `internal/gitctx`;
- change the `git()` helper's error mapping.

Verify:

```sh
go test ./internal/gitctx/ && gofmt -l internal/gitctx
```

Expected result: all gitctx tests pass and gofmt prints nothing.

# Branch B, planning phase

Gated by A. B1 restructures how the plan is built; B2 adds containment on top.

### Step B1: ordered plan via `planBatchBranches`

Create `internal/cmds/pr_batch_plan.go`:

```go
// planBatchBranches turns matched branch names into the ordered create-batch
// plan. Branches with no commit subject are skipped; one note per skipped
// branch is returned in notes so the caller owns where notes go, keeping the
// function testable without writers.
//
// Ordering: tip date ascending, ties broken by ancestry (parent first),
// then lexical. Every git lookup degrades to a default (0 date, "" subject,
// ancestry false), so there is no error return.
func planBatchBranches(root string, matched []string, base string) (items []BatchReceiptItem, notes []string)
```

Behaviour, in order:

1. For each branch in `matched` (Run already applies `sort.Strings`, which the stable sort needs as deterministic input), collect `{branch, tipDate: gitctx.BranchTipDate(root, branch), subject: gitctx.CommitSubject(root, branch)}`. Subject `""` produces note `skipped: <branch> (no commit subject)` and drops the branch.
2. Sort survivors with `sort.SliceStable`: tip date ascending; on equal dates, `gitctx.IsAncestor(root, a, b) == true` puts `a` first; an `IsAncestor` error counts as false, falling through to lexical.
3. Build `BatchReceiptItem{Branch: branch, Title: subject, Base: base}` for each survivor.

Change `createBatchCmd.Run` in `internal/cmds/pr_batch.go`: replace the loop that computes subjects and appends items, and keep the existing empty-plan error for now, with one call:

```go
items, notes := planBatchBranches(ctx.Repo.Root, matched, d.Base)
for _, note := range notes {
	fmt.Fprintln(ctx.Stderr, note)
}
```

The empty-plan message ("no commits to title any matching branch") is unchanged in this step; B2 replaces it.

Create `internal/cmds/pr_batch_plan_test.go` with a date-pinning fixture:

```go
// batchRepoAt wraps the batchRepo pattern, setting GIT_COMMITTER_DATE and
// GIT_AUTHOR_DATE to dates[branch] (RFC 3339, e.g. "2024-01-02T03:04:05Z")
// per commit. Branches absent from dates commit without overrides.
func batchRepoAt(t *testing.T, branches map[string]string, dates map[string]string) *gitctx.Repo
```

Test cases:

1. Distinct dates order oldest first regardless of lexical order (`z` at T1, `a` at T2 yields `z, a`).
2. Equal dates keep lexical order.
3. A stacked pair with identical committer dates lists the parent first. The fixture commits each branch from main, so build this pair inline with the same env technique: commit parent, branch child from parent, commit child with the parent's date.
4. The no-subject note text is exact and the branch is absent from items.

Update `TestBatchPlanSortedLexically` in `internal/cmds/pr_batch_test.go` to use `batchRepoAt` with one pinned date for all three branches. As written it relies on commits landing in the same second, which flakes when the test crosses a second boundary.

Do not:

- add containment checking (B2 owns that);
- touch the `--yes` loop, `ResolveCreateDefaults`, or the receipt type;
- change stderr note formatting beyond what `planBatchBranches` emits;
- sort anywhere else (drop the implicit assumption that lexical equals correct order, but keep `sort.Strings(matched)` as the tie-break input).

Verify:

```sh

```

Expected result: all batch tests pass, including the reworked lexical test (pinned dates) and the existing `--yes` tests, whose fixtures commit near-simultaneously and now tie into lexical order.

### Step B2: containment preflight and the empty-plan message

In `internal/cmds/pr_batch_plan.go`, extend the per-branch pass with the containment check, after the subject check:

```go
// A branch whose tip is contained in base would open an empty pull request;
// skip it. UniqueCommitCount(base..branch) == 0 is the local containment
// test. When base does not resolve locally (server-only branch name), the
// check is inconclusive: do not skip, and let the POST surface the real
// error.
n, err := gitctx.UniqueCommitCount(root, base, branch)
if err == nil && n == 0 {
	// note: skipped: <branch> (already in base)
}
```

The check also drops the base branch itself when PATTERN matches it, which today would open an empty PR base-into-base.

In `internal/cmds/pr_batch.go`, replace the empty-plan error so it names both skip reasons, still `ExitUsage`:

```go
&cli.Error{

}
```

# Branch C, --yes loop hardening

Independent of A and B logically; merge-adjacent to B in `createBatchCmd.Run` (see the decision tree).

### Step C1: wait for PR page availability

In `internal/cmds/pr_batch.go`, add:

```go
// pageProbeClient is an unauthenticated HTTP client used only to check that
// a just-posted PR page is reachable. It never sends the token.
var pageProbeClient = &http.Client{Timeout: 2 * time.Second}

// pollPRPage GETs url up to attempts times, delay apart, without decoding
// the body or sending credentials. It reports whether any response had a
// status below 400; transport errors count as not-ready.
func pollPRPage(client *http.Client, url string, attempts int, delay time.Duration) bool
```

Implementation: loop `attempts` times, `http.NewRequest("GET", url, nil)` with no `Authorization` header, probe, and return true on the first status below 400. Close every body. Sleep `delay` between attempts, skipping the final sleep. Return false after the last attempt.

In the `--yes` loop, after a successful `CreatePullRequest` and the existing `Number`/`URL` fill-in:

```go
if !pollPRPage(pageProbeClient, pr.HTMLURL, 5, 500*time.Millisecond) {
	fmt.Fprintf(ctx.Stderr, "note: %s page not confirmed available before continuing\n", items[i].Branch)
}
```

The POST loop stays strictly sequential and stop-on-first-failure is unchanged. A timeout is never an error; on a private repo the unauthenticated probe may warn every time, and that is accepted noise.

Add `net/http` and `time` imports. Test cases in `internal/cmds/pr_batch_test.go`:

1. `pollPRPage` returns true when the server answers 500, 500, then 200 (delay 1 ms).
2. It returns false when every response is 500.
3. It stops at `attempts`: the handler counts requests and `attempts = 3` yields exactly 3 GETs.
4. It sends no `Authorization` header (the handler asserts the header is empty).
5. A `--yes` happy path against a server whose `HTMLURL` 404s forever still exits 0 with the unchanged receipt, and stderr carries the note line.

Do not:

- send the token on the probe or decode the probe body;
- retry the POST itself, or make the wait configurable by flag or config;
- wait in dry-run, or gate the next POST on a successful probe;
- change the receipt for a timed-out probe.

Verify:

```sh
go test ./internal/cmds/ -run 'TestBatch|TestPollPRPage' && go test ./internal/cmds/
```

Expected result: poll unit cases and all batch tests pass, with the happy-path 404-forever case confirming the wait degrades to a stderr note.

### Step C2: duplicate-PR responses are skips

In `internal/cmds/pr_batch.go`, add:

```go
// looksLikeDuplicatePR reports whether a server error message indicates the
// batch PR already exists for that head branch. Provisional by design: the
// exact Forgejo wording is unverified against a live instance, so refine
// this matcher and its test together when the real message is confirmed.
func looksLikeDuplicatePR(msg string) bool {
	return strings.Contains(strings.ToLower(msg), "already exists")
}
```

In the `--yes` loop's error branch, before the stop-on-failure path:

```go
var apiErr *api.APIError
if errors.As(err, &apiErr) {
	items[i].Error = serverMessage(apiErr)
	if looksLikeDuplicatePR(items[i].Error) {
		fmt.Fprintf(ctx.Stderr, "skipped: %s (PR already exists)\n", items[i].Branch)
		continue
	}
} else {
	items[i].Error = err.Error()
}
```

A duplicate item carries the server message verbatim in `Error` with `Number`/`URL` unset, and the batch continues with the remaining branches. A batch that ends without other failures exits 0 with the full receipt. Any other failure class keeps the existing partial-receipt write and stop-on-first-failure return.

Test cases in `internal/cmds/pr_batch_test.go`:

1. The server answers 422 `{"message":"PR already exists for that branch -> main"}` for the second of three branches: stderr carries `skipped: b2 (PR already exists)`, the third branch is still posted, the final receipt has all three items, `items[1].Error` is verbatim, `items[1].Number`/`URL` are omitted, exit 0.
2. A duplicate followed by a real failure yields a partial receipt including the duplicate item and `ExitRuntime`.
3. `looksLikeDuplicatePR` is positive on the release's example wording and negative on `"validation failed"`.

Do not:

- add dry-run preflight via the PR search endpoint (deferred in the release);
- rename receipt fields or add a `skipped` field;
- dedupe branches against each other;
- change handling of any other failure class.

Verify:

```sh
go test ./internal/cmds/ && go vet ./internal/cmds/
```

Expected result: all batch tests pass and vet is clean.
