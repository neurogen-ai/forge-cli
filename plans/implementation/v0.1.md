# Implementation plan — v0.1

## Context

- **What exists:** Only planning docs. `plans/PRD.md` defines the product contract (command surface, auth chain, fetch≠save, exit codes); `plans/releases/v0.1.md` defines scope, package layout, flag matrix, and test plan. There is no Go code, no `go.mod`.
- **Files touched:** everything under `cmd/forge/` and `internal/{cli,api,auth,config,gitctx,cmds,store}` per `releases/v0.1.md` §2.
- **Depends on:** `plans/PRD.md` (behavioral authority), `plans/releases/v0.1.md` (layout + flags + config schema). Do not restate those decisions here; this plan references them.

## Goals

1. Ship every checklist item in `releases/v0.1.md` §1 as a series of small branch-PRs.
2. Each step fits one agent context window; each step states its own contracts so steps are independently implementable.
3. Zero third-party dependencies; stdlib only (`net/http`, `encoding/json`, `testing`, `httptest`).

## Success criteria

- All acceptance criteria 1–6 of `releases/v0.1.md` §5 pass.
- `go vet ./...` and `go test ./...` clean.
- Dependency direction holds: `cmds → api/auth/config/gitctx/store → stdlib`; nothing imports `internal/cmds`.

## Tests

Per-package tests are specified inline in each branch below. The integration acceptance run (`releases/v0.1.md` §5) is Branch H.

## Logical git commits

Each branch = one PR = one or more commits:
- B0: `chore: scaffold module, cli skeleton, command registry`
- B1: `feat(config): toml subset parser + layered config`
- B2: `feat(gitctx): remote URL parsing + repo detection`
- B3: `feat(auth): token resolution chain with credential fill`
- B4: `feat(api): http client, error type, pagination`
- B5: `feat(pr): pulls endpoints + pr commands`
- B6: `feat(issue): issues endpoints + issue commands`
- B7: `feat(store): save family + cache flush/path`
- B8: `docs+chore: verbose logging polish, README, acceptance run`

```
B0 scaffold (registry, exit codes, arg skeleton)
├── B1 config ──────────┐
├── B2 gitctx ──────────┤
└── B4 api client ──────┤
    ├── B3 auth (needs B2's host concept; only types from B0)
    │                    │

    │                         both touch cmd wiring — see sequencing note)

                              conflicts with B5/B6 only in main.go registration)

```

**Sequencing note (the one real bottleneck):** all commands register themselves in
`cmd/forge/main.go` via one `Register(...)` line each. B5, B6, B7 each add lines
there — merge them sequentially or rebase trivially. Everything else is fully
parallel.

**Parallelizable:** {B1, B2, B4} together after B0; {B3} after B2; {B5, B6, B7}
together after B3/B4/B1; B8 last.

# Branch A — Scaffold (B0)

PR: module init, exit-code mapping, global flag parsing, `Command` registry, `forge --help`. No Forgejo calls.

### Step A1: module + cli core

Create:

```
go.mod                      # module forge, go 1.22
cmd/forge/main.go           # main(): build empty Ctx, Register(builtin placeholder "version"), cli.Run
internal/cli/cli.go         # Run(os.Args[1:], reg, ctxFactory) int
internal/cli/exit.go        # Exit code constants
internal/cli/registry.go    # Command interface + Registry
```

Contracts (exact):

```go
// internal/cli/exit.go
package cli
const (
    ExitOK       = 0
    ExitRuntime  = 1 // API/runtime error        (PRD §10)
    ExitUsage    = 2 // bad flags / missing value
    ExitContext  = 3 // not in repo / no remote
    ExitAuth     = 4 // no token / rejected
    ExitNetwork  = 5 // timeout / conn failure
)

// internal/cli/registry.go
package cli
type Command interface {
    Name() string                      // e.g. "pr conversation"; "" is never valid
    Summary() string                   // one line for help
    Run(args []string, ctx *Ctx) error
}
type Ctx struct {                       // filled progressively by later branches;
    Stdout, Stderr io.Writer            //   fields added ONLY here, never ad-hoc params
    Verbose          bool
    GlobalFlags      GlobalFlags
}
type GlobalFlags struct {
    Host, Owner, Repo, Token, ConfigPath string
    TimeoutSeconds int
}
type Registry struct{ /* map[string]Command */ }
func NewRegistry() *Registry
func (r *Registry) Register(c Command)          // panics on duplicate Name()
func (r *Registry) Lookup(path string) Command  // nil if unknown

// internal/cli/cli.go
func Run(argv []string, reg *Registry, base *Ctx) int
// Parses leading global flags (--host --owner --repo --token --config --verbose/-v
// --timeout N) anywhere before the command path; dispatches argv[0] as command path,
// rest as args. Unknown command ⇒ print usage to stderr, return ExitUsage.
// Command errors: return values are mapped by errors.As on *cli.Error:
type Error struct{ Code int; Msg string; Hint string }
func (e *Error) Error() string // "msg\nhint: hint"
```

`main.go` prints top-level help listing registered commands when argv is empty.

Out of scope: any config loading, auth, HTTP, subcommand logic beyond a `version` command printing `forge-cli v0.1`.

Verify: `go build ./... && ./forge version && echo $?` → `forge-cli v0.1` then `0`. `./forge nosuch; echo $?` → usage + `2`.

Abstractions designed to absorb: new global flags land only in `GlobalFlags`; new commands touch only their own file + one `Register` call.

# Branch D — Auth (B3)

PR: token resolution chain. Depends on: B0, B2 (for host type only).

### Step D1: resolver

Create `internal/auth/auth.go`:

```go
package auth
// Resolve returns the first non-empty of, in order (PRD §5):
//   explicitToken > FORGE_TOKEN env > "" (caller consults config before calling;
//   this package does NOT read config files).
// If still empty, runs: printf 'protocol=https\nhost=%s\n\n' <host> | git credential fill
// and returns the password= line. Any fill failure or empty password returns ErrNoToken.
func Resolve(host, explicitToken string) (string, error)
var ErrNoToken = errors.New("no token found")
// Caller maps ErrNoToken → cli.Error{Code: cli.ExitAuth, Hint: "check your git
// credential helper stores a token for this host, or pass --token"} (PRD §5 wording).
```

Implementation notes: `exec.Command("git", "credential", "fill")` with stdin pipe; set `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never` in the child env so it can never hang on a prompt — fail instead. Close stdin promptly. Never log the token.

Tests (`auth_test.go`): fake `git` shim earlier in PATH (test writes a script that echoes fixed credential output) — assert order explicitToken > env > fill; fill-failure ⇒ ErrNoToken.

Out of scope: token refresh, OAuth expiry handling, scope introspection, config-layer tokens (those are passed in as explicitToken by the wiring step).

Verify: `go test ./internal/auth/`.

Absorbs: a new auth source = one clause prepended in Resolve; callers unchanged.

### Step F1: context wiring (do this first, alone)

Extend `internal/cli/cli.go`'s `Ctx` construction in `cmd/forge/main.go`:

```go
// Resolution performed once at startup, in this exact order per key (PRD §6):
// flag > env (FORGE_HOST/FORGE_OWNER/FORGE_REPO/FORGE_BASE) > local cfg > global cfg > git-derived.
// Steps:
//  1. cfg := config.Load(config.DefaultGlobalPath(), config.LocalPath(root), true)
```

### Step F3: pr commands

Create `internal/cmds/pr.go` registering four Commands:

- `pr create`: required `--title` (else ExitUsage naming it). Head default: `--head` > env > `gitctx.CurrentBranch()`; still "" ⇒ ExitUsage. Base default: `--base` > env > cfg Defaults.Base; still "" ⇒ ExitRuntime with hint "cannot determine base branch; pass --base". Prints created PR as JSON.
- `pr get N`, `pr list [--state --page --limit]`: straight passthrough, JSON array/object to stdout.
- `pr conversation N [--format flat|grouped]`: fetches issue comments (`GET /repos/{o}/{r}/issues/N/comments`) + reviews + per-review comments (same calls as `api.GetIssueComments`, `GetReviews`, `GetReviewComments`). Grouped (default): `{"comments":[…],"reviews":[{"…review fields","comments":[…]}]}`. Flat: single array sorted by `created_at`, each item tagged `"kind":"comment"|"review"|"review-comment"` (review-comments keep their review id under `"review_id"`). Errors bubble via `cli.Run` mapping (`errors.As(*api.APIError)` ⇒ ExitRuntime; `IsNetwork` ⇒ ExitNetwork).

Commit style: F2 and F3 as separate commits in one PR.

Out of scope: timeline endpoint, review approve/request-changes, comment authoring, saving (B7).

Verify: `go test ./...`; against a live instance: `forge pr list --limit 3 | jq length` == 3.

Absorbs: a changed conversation shape = one render function in pr.go; new pr verb = one file-local Command + Register.

# Branch H — Store: save + cache (B7)

PR: the only filesystem-writing code. Depends on: B1 (savedirs), B4, and F3/G2 patterns (calls their api funcs directly — store depends on api, not on commands).

### Step H1: store package

Create `internal/store/store.go`:

```go
package store
// Save writes <dir>/<repo>-<N>.json; if that exists, appends -<unix-ts> before .ext.
// Creates dir with 0755. Returns the written path.
func Save(dir, repo string, number int, data []byte) (string, error)
// Flush removes regular files directly inside each dir (NOT recursive, NOT the dirs
// themselves unless empty afterwards — then remove the dir too). Returns removed
// paths. Refuses (returns error listing paths) if any dir resolves outside root
// unless allowOutside=true.
func Flush(root string, dirs []string, allowOutside bool) ([]string, error)
// ResolveDirs(cfgSavedirs map[string]string, root, home string) []string
```

### Step H2: save + cache commands

Create `internal/cmds/save.go` (`save pr-conversation N`, `save issue N [--dir]`) — reuses the exact same fetch functions as F3/G2 by calling `internal/api` (duplicate the ~10-line composition, do not import `internal/cmds`).
