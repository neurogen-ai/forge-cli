# Implementation plan — v0.2.0

## Context

- **What exists:** forge-cli v0.1.2 works end to end: nested-command registry (`internal/cli/registry.go`), typed errors mapped to exit codes in `cli.Run`, staging preflight (`cmd/forge/diagnose.go`) that fires four API probes (version/token/owner/repo) before every API command from `wire()` in `cmd/forge/main.go`. `wire` builds the base URL as hardcoded `"https://" + host`; `normalizeHost` strips any user-supplied scheme. Savedir defaults are repo-relative `.forge/prs` and `.forge/issues` (defined in `internal/config/config.go`), with `~/` expansion and absolute paths already supported by `store.ResolveDirs`.
- **Files touched:** `internal/config/config.go` (+ tests), `internal/cli/registry.go`, `internal/cli/cli.go` (+ tests), `cmd/forge/main.go`, `cmd/forge/diagnose.go` (+ test), `cmd/forge/protocol.go` (new, + test), `internal/store/store.go` (+ test), `internal/cmds/cache.go`, `README.md`, `plans/releases/v0.2.0.md`.
- **Depends on:** `plans/releases/v0.2.0.md` (behavior authority), `plans/PRD.md` §5–§8 (precedence chain, exit codes, fetch-vs-save), `plans/implementation/v0.1.3.md` (the final error handler in `cli.Run` this release extends).
- **Precondition:** v0.1.3 (per-command help) must land on main first. All v0.2.0 branches cut from main after that merge.

## Goals

1. Protocol is configurable so plain-http servers work: `--host http://x` (embedded scheme), or `[api] protocol = "http"` in config. Connecting over http to a non-localhost host prints a one-line warning to stderr.
2. Diagnosis is lazy: `wire` proceeds naively with zero preflight requests; the four-stage probe runs only after a command fails, appended below the original error. When diagnosis finds nothing wrong it says so plainly ("failed to diagnose").
3. Default savedirs move from the repo (`.forge/*`) to the XDG state directory (`~/.local/state/forge/*` or `$XDG_STATE_HOME`). The flush outside-root guard no longer demands `--yes` for paths under forge's own state directory.

## Success criteria

- All acceptance criteria of `plans/releases/v0.2.0.md` pass (they are pinned per branch below).
- An API command that succeeds makes zero requests beyond its own endpoint calls (measured in tests by counting httptest hits).
- `go vet ./...` and `go test ./...` green; existing tests unmodified except where a step says so.

## Abstractions

- **Scheme resolution sits in one precedence chain** (`embedded scheme in host > [api] protocol > "https"`), implemented as two pure functions in one new file (`cmd/forge/protocol.go`). Absorbs future additions like a `--protocol` flag or a FORGE_PROTOCOL env var: each new source appends one slot in `resolveBaseURL`, nowhere else.
- **`Ctx.Diagnose func() *cli.Error`**: a plain hook field beside `Prepare`, set only by `wire` for API commands, consumed only at one place in `cli.Run`. Absorbs future diagnosis policies (only-on-network, opt-out flag): policy changes edit the single call site and the closure, never commands. Commands stay diagnosis-blind; `mapErr` stays dumb.
- **Forge-state-dir carve-out** (`store.IsForgeStateDir`) rather than weakening the outside-root guard wholesale: flush protection generalizes as "safe when the target is forge's own managed area". Absorbs a future `state.json` ledger and release notes savedirs: new managed locations register in one predicate, not in every fs-writing path.

// splitScheme accepts "git.example.com", "http://git.example.com",

func splitScheme(raw string) (host, scheme string)

### Step B2: the Diagnose hook and its single consumer

**2a.** `internal/cli/registry.go`, add to `Ctx` right after `Prepare`:

```go
// Diagnose re-runs the staged host/token/owner/repo probes after a
// command has already failed. It is set only for API commands. Returns
// nil when nothing further should be printed (call sites are expected
// to have wrapped diagnose-all-clear outcomes themselves).
Diagnose func() *cli.Error
```

**2b.** `cmd/forge/diagnose.go`, add the closure factory (so its mapping is testable without running `wire`):

```go
// diagnoseClosure returns the Ctx.Diagnose implementation for an API
// command: run the four-stage probes; on a pinpointed layer return that
// typed error; when every stage passes return the explicit
// "failed to diagnose" outcome rather than silence.
func diagnoseClosure(p repoProbes, host, owner, repoName string) func() *cli.Error {
	return func() *cli.Error {
		if err := diagnoseRepo(p, host, owner, repoName); err != nil {
			return err
		}
		return &cli.Error{
			Code: cli.ExitRuntime,
			Msg:  "failed to diagnose",
			Hint: "host, token, owner, and repository all verify OK; the reported failure is specific to the request itself",
		}
	}
}
```

`cmd/forge/main.go`, at the end of `wire` (after client construction, replacing the deleted eager call):

```go
ctx.Diagnose = diagnoseClosure(ctx.API, host, owner, repoName)
return nil
```

**2c.** `internal/cli/cli.go`, final handler in `Run`. After the v0.1.3 shape (usage-error help page), extend so the whole tail reads:

```go
code := reportError(ctx.Stderr, err)
var cerr *cli.Error
if errors.As(err, &cerr) {
	switch cerr.Code {
	case ExitUsage:
		fmt.Fprintln(ctx.Stderr)
		PrintHelp(ctx.Stderr, cmd)
	case ExitRuntime, ExitNetwork:
		if ctx.Diagnose != nil {
			if d := ctx.Diagnose(); d != nil {
				fmt.Fprintln(ctx.Stderr)
				fmt.Fprintln(ctx.Stderr, d.Msg)
				if d.Hint != "" {
					fmt.Fprintf(ctx.Stderr, "hint: %s\n", d.Hint)
				}
			}
		}
	}
}
return code
```

Pin the rules, do not deviate:
- Diagnosis output is additive: the original error from `reportError` prints first, then a blank line, then the diagnosis. Exit code stays the ORIGINAL command's code; a diagnosis with `Code: ExitRuntime` never upgrades a network exit to 1.
- `ExitAuth` and `ExitContext` skip diagnosis: those messages already name the culprit (token rejected; `pr create`'s branch disambiguation from v0.1.2), and re-probing adds latency for no information.
- Non-`*cli.Error` errors skip diagnosis (there is no code to inspect).
