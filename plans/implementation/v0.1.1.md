# Implementation plan — v0.1.1

## Context

- **What exists:** forge-cli v0.1 works end to end (`plans/releases/v0.1.md`). All list endpoints funnel through one generic function, `api.List[T]` in `internal/api/pagination.go`, called by `ListPullRequests` and `ListIssues`. The wiring preflight (`cmd/forge/diagnose.go`) already verifies host/token/owner/repo before any API command runs. On repos where no PR has ever been created, Forgejo answers `GET /repos/{o}/{r}/pulls` with `404 {"message":"The target couldn't be found."}`, which escapes `mapErr` as a raw error even though the real answer is "there are none yet". Scope decision in `plans/releases/v0.1.1.md`.
- **Files touched:** `internal/api/pagination.go`, `internal/api/pagination_test.go`, `internal/cmds/pr.go`, `internal/cmds/issues.go`, `internal/cmds/cmds.go`, `internal/cmds/pr_test.go`, `README.md`.
- **Depends on:** `plans/releases/v0.1.1.md` (behavior spec), `plans/PRD.md` §4 (JSON-on-stdout contract, exit codes).

## Goals

1. A 404 from a collection endpoint reads as an empty list, never as an error.
2. Single-item 404s keep failing loudly.
3. The rule lives in exactly one place; future list endpoints inherit it for free.

## Success criteria

- Fresh repo, zero PRs: `forge pr list` exits 0, stdout is `[]`, stderr says `no pull requests found in <owner>/<repo>`. Same shape for `issue list`.
- `forge pr list -v` also shows the raw swallowed response on stderr.
- `forge pr get 99` still exits 3 with the server message.
- `go vet ./...` and `go test ./...` clean.

## Tests

Specified inline per branch. Acceptance run is Branch B, Step B2.

## Logical git commits

- A1: `feat(api): treat 404 on paginated collections as an empty list`
- B1: `feat(cmds): print 'no <items> found' when a list comes back empty`
- B2: `docs: document empty-list behavior for pr/issue list`

---

## Decision tree

```
A. api layer: List swallows collection 404s   (bottleneck)
└── B. cmds layer: empty-list note
    ├── B1 empty-note helper + wire into pr list / issue list
    └── B2 docs + acceptance run   (needs B1)
```

One bottleneck: nothing compiles-behaves correctly until A merges, because B's tests assert exit 0 on a 404 server. B1 must not start before A lands. Within B, B1 then B2, strictly sequential (B2 documents B1's output text). This release is small enough that parallelism buys nothing; do not split further.

## Abstractions

- **404-as-empty inside `api.List[T]`** (not in callers): every current and future collection endpoint passes through it, so the rule cannot be forgotten per endpoint. Absorbs: new list commands, a later decision to treat another status (say 410) as empty, or reverting the behavior — each lands in one function.
- **`emitEmpty` helper in `internal/cmds`**: names the empty-collection note once. Absorbs: wording changes or a `--quiet` flag later.

# Branch A — api layer: collection 404 means empty

PR: `List[T]` converts a 404 on the first page into `(nil, nil)` and logs it. No caller changes.

### Step A1: swallow 404 in List, log under verbose

File: `internal/api/pagination.go`.

In `func List[T any](c *Client, startPath string, q url.Values) ([]T, error)`: when `c.getPage(next, &items)` returns an error, check it with `errors.As` against `*APIError`. If `apiErr.Status == http.StatusNotFound` **and** this is the first iteration of the loop, call `c.logf("GET %s -> 404 (treated as empty)", next)` and return `(nil, nil)`. A 404 after the first page still fails: the server told us there were more items, so a mid-walk 404 is a real problem, not an empty collection. Implement the distinction with a `first bool` (or `i == 0`) check in the existing `for range maxPages` loop; no new types.

Do NOT touch:
- `getPage` (it must keep returning `*APIError`; the conversion belongs to `List`),
- `RepoExists` and the diagnose probes in `cmd/forge/diagnose.go` (a 404 there still means wrong name/private/missing scope),
- `mapErr` in `internal/cmds/cmds.go`,
- single-item calls (`GetPullRequest`, `GetIssue`, `GetIssueComments`, `GetReviews`, `GetReviewComments`); they do not go through `List` and keep failing on 404,
- `maxPages`.

Tests, file `internal/api/pagination_test.go` (extend):
1. httptest server whose `/api/v1/items` returns 404 with body `{"message":"The target couldn't be found."}` → `List[struct{}](...)` returns `(nil, nil)`.
2. First page returns 200 plus `Link: <next>; rel="next"`; second page returns 404 → `List` returns an error wrapping `*APIError` with status 404.
3. Server returns 403 on first page → `List` returns the `*APIError` untouched.
4. With a logger attached (`Client`'s existing verbose logger), case 1 writes a line containing `treated as empty` to the logger's writer.

Verify:

```
go test ./internal/api/ -run TestList && go vet ./...
```

Expected: all listed cases pass; package builds.

# Branch B — cmds layer: empty-list note

### Step B1: emitEmpty helper, wire into pr list and issue list

Files: `internal/cmds/cmds.go`, `internal/cmds/pr.go`, `internal/cmds/issues.go`.

Add to `internal/cmds/cmds.go`:

```go
// emitEmpty tells the user a collection came back empty without polluting
// stdout's JSON channel.
func emitEmpty(ctx *cli.Ctx, what, owner, repo string) {
	fmt.Fprintf(ctx.Stderr, "no %s found in %s/%s\n", what, owner, repo)
}
```

No new types, no interface. Callers pass the plural noun ("pull requests", "issues").

Wire into both Run methods after a successful call, before `writeJSON`:

- `internal/cmds/pr.go`, `prListCmd.Run`: after `ListPullRequests` succeeds, `if len(prs) == 0 { emitEmpty(ctx, "pull requests", o, r) }`. Keep writing `prs` (which json-marshals to `[]` for a nil slice) to stdout exactly as today.
- `internal/cmds/issues.go`, `issueListCmd.Run`: same with `"issues"`.

The note fires on any zero-length result, whether it came from a swallowed 404 or a genuinely empty page. Do not try to distinguish them here; Branch A already logged the raw response for verbose runs.

Do NOT:
- change `writeJSON`, exit codes, or the JSON shapes,
- add empty-notes to single-item commands (`pr get`, `pr conversation`, `issue get`, `save *`): their 404 stays an error per `releases/v0.1.1.md`,
- touch `fetchConversation`.

Tests, extend `internal/cmds/pr_test.go` (and the matching issues test file if one exists; otherwise add `issues` coverage to `pr_test.go`'s pattern with a fake client):
1. Fake API returning `(nil, nil)` from ListPullRequests → Run exits nil, stdout is `[]\n`, stderr contains `no pull requests found in alice/proj`.
2. Fake returning one PR → stderr has no note.

Verify:

```
go test ./internal/cmds/ && go build ./...
```

Expected: tests pass, binary builds.
