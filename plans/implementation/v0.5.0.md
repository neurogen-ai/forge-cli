# Implementation plan, v0.5.0

## Context

**What exists:** after v0.4.2, main has the full object-management verb set (edit, labels, browse, releases) on the typed Forgejo client, the gh-style receipts, TTY-aware JSON/table output, the exit-code contract 0–5 in `internal/cli/exit.go`, the central `forge.Version` constant, and one working gap: the command surface is spelled for forge's own history, not for `gh` muscle memory, and a `tuicr` `ForgeBackend` cannot yet run a review lifecycle through it.

**Areas touched:** `internal/cli` (Ctx gains Stdin), `internal/cmds` (`pr.go`, `comments.go`, `pr_review.go`, new `api.go`, `pr_checkout.go`, `stdin.go`, `cmds.go`), `internal/api` (`pulls.go`, `types.go`), `internal/gitctx` (fetch and checkout helpers), `cmd/forge/main.go`, repo-root `version.go`, `README.md`, `plans/releases/v0.5.0.md`, new `scripts/probe-v0.5.0.sh`.

**Depends on:** `plans/releases/v0.5.0.md` is the authority for scope, alias policy, and the anchored-comment probe-first rule. `plans/implementation/v0.4.2.md` supplies the baseline the release doc presumes (version constant, edit/label/browse/release verbs). `plans/PRD.md` §§5–10 covers precedence, output, and error contracts. The archived proposals (`plans/proposals/archive/`, all v0.3.0 material) and the archived discovery plan (`plans/implementation/archive/v0.5.0-discovery.md`) carry no active decisions; the tuicr `ForgeBackend` trait is an external source, derived in branch J, not restated here. No `design/*` decisions exist.

**Preconditions:** v0.4.2's three PRs are merged on main; every branch cuts from that baseline. Merging to main is out of scope for every branch and PR; each PR ends at a reviewed, mergeable state, and the release doc records where each PR ends.

**Descope homes (from the release doc, each with a named boundary):**

- `forge search` and `forge pr sync-status` stay out (moved to v0.6.0, "neither serves the tuicr contract"). Home: no branch may create `internal/api/search.go`, `internal/cmds/search.go`, or `internal/cmds/pr_sync.go`; J1 records the deferral in the release doc.
- `pr merge --dry-run` stays out ("a dry run could only repeat the local containment check"). Home: no branch touches `pr_merge.go`; no command may grow a `--dry-run` flag.
- Review-thread editing/deletion, a `pr comment view` listing verb, and `--json <fields>` selection stay out. Home: C, F, and G boundaries forbid them; J1 records the deferral.
- Multi-forge ambitions, review UI, session state, and diff rendering stay permanently out. Home: every branch boundary.
- Anchor ranges stay out this release ("range if the instance supports it" is conditional). Home: F's probe script records whether the acceptance instance supports ranges and files the finding for v0.6.0; F3 forbids a range flag.

## Goals

1. `forge pr view N` becomes the documented canonical spelling of `pr get`; both work, receipts unchanged, and the JSON payload carries every field tuicr's `get_pull_request`/`get_pull_request_info` reads.
2. `forge pr comment N --body T` becomes the canonical comment verb (with `--body -` for stdin), and `forge pr review N --approve|--request-changes|--comment [--body T]` becomes the canonical review form; old spellings stay as compatibility aliases with unchanged receipts.
3. Anchored inline comments (`pr comment N --file P --line L [--side old|new]`) let tuicr post per-hunk comments, shaped by a live-instance probe before the wire format is committed.
4. `forge pr checkout N` fetches the PR head into the local repo, detached by default, `--branch B` to name a local branch, with no Forgejo mutation.
5. `forge api <path> [--method M] [--input @file|JSON|-] [--q k=v]... [--jq Q]` gives agents the authenticated escape hatch, so CLI omissions never block a script.
6. The numeric index is accepted wherever it appears (`forge pr merge 11 --merge` and `forge pr merge --merge 11` both work) through one flag-aware scanner shared by every N-taking command.
7. The tuicr `ForgeBackend` audit, the gh-to-forge mapping, the exit-code and JSON contracts, and the six-command agent paragraph land in the docs, and the release closes on a real-instance lifecycle run.

## Success criteria

- Acceptance battery passes at every commit: `go vet ./...`, `gofmt -l .` prints nothing, `go build ./...`, `go test ./...`. No third-party dependencies.
- `plans/releases/v0.5.0.md` §1 checklist is fully ticked at J3. Each §1 box maps to one branch: pr view to G, pr comment to C, pr review flags to D, anchored comments to F, checkout to H, forge api to E, flag placement to A, contract audit and README to J, lifecycle acceptance to J, version bump to A1.
- `forge pr view 7` and `forge pr get 7` print byte-identical JSON; the payload includes title, body, author, head/base refs and SHAs, state, draft, updated timestamp, HTMLURL, and merged/mergeable where the instance exposes them.
- `forge pr comment 5 --body hi` and `--body -` with piped stdin both produce the existing `CommentReceipt`; a missing body exits 2 before any request. `forge pr review 5 --request-changes` without `--body` exits 2 before any request; `--approve` needs no body.
- An anchored comment on the acceptance instance lands with path and line recorded in the receipt; an instance that cannot anchor fails with exit 1 and the server message in the hint, never a silently unanchored comment.
- `forge pr checkout 5` checks out the head SHA detached; `--branch B` creates local branch B at that SHA; cross-repo heads fetch from the head repository's clone URL; no request mutates Forgejo.
- `forge api repos/{o}/{r}/swagger.v1.json` writes a valid JSON response; a text response passes through byte-exact; `--jq` runs system jq with the filter as one argv element and no shell; missing jq exits 2 with an install hint; a failed filter exits 1 and keeps jq's stderr.
- `forge pr merge 11 --merge` and `forge pr merge --merge 11` both merge; `forge pr conv --min-unresolved 2 11` resolves index 11, not 2; the same holds for every N-taking command (~10).
- `forge version` prints `forge-cli v0.5.0`, verified in J3's binary battery; every new `-h` page exits 0 and shows both spellings where an alias exists.
- The exit-code table in README matches `internal/cli/exit.go` line for line (grep-able check in J2), and the tuicr `ForgeBackend` audit table in `plans/releases/v0.5.0.md` resolves every trait method to a documented command or a recorded gap.
- The release-closing lifecycle run (`pr list → view → diff → comment → anchored comment → review --approve` and `--request-changes → merge`) works on a real Forgejo instance from a fresh clone with only `FORGE_TOKEN` set. J3 does not tick the checklist without it; an unreachable instance stops J and reports, it never gets papered over.

## Branch naming

Ordinary branches are `v0.5.0-<topic>`, PR heads are `v0.5.0-PR-<topic>`; topics are lowercase kebab-case and nothing else. Ordinary names validate against `^v\d+\.\d+\.\d+-(?!PR-)[a-z0-9-]+$`, PR heads against `^v\d+\.\d+\.\d+-PR-[a-z0-9-]+$`. A renamed branch is deleted and rebranched, never forked under a variant.

├── E  v0.5.0-api-passthrough    E1 → E2            (waits on A, B)

│
│ closing branch, merges everything
└── J  v0.5.0-contract-close     J1 → J2 → J3       (waits on A through H)

Merge ledger, every arrow an actual merge, dependency into dependent:

```text
A → C     B → C
A → D
A → E     B → E
A → F     B → F     C → F
G → H
A → J     B → J     C → J     D → J     E → J     F → J     G → J     H → J
C → v0.5.0-PR-gh-verbs                D → v0.5.0-PR-gh-verbs
E → v0.5.0-PR-agent-transport         F → v0.5.0-PR-agent-transport
```

PR 1's head carries only C and D, so it merges first and cleanly. PR 2's head will contain PR 1 commits through the direct B→E and C→F merges; that is the point of merging where the dependency exists, and the diff against main turns clean the moment PR 1 lands. PR 3 and PR 4 are single-branch PRs; their heads are `v0.5.0-checkout` and `v0.5.0-contract-close`, and a PR head with one branch gets no `PR-` branch of its own.

Shared seams:

- Registration seam. C, D, E, F, and H each append their own `Register` entries in `cmd/forge/main.go` (or their family list in `internal/cmds`), touch nothing else's, and whoever lands second rebases. The seam is the existing `cli.Command`/longest-match dispatch contract (`plans/implementation/archive/v0.3.1.md`).
- `internal/cmds/cmds.go` is owned by A (`stripFlags`, `parseIndex`); B's stdin helper and E's flag helper live in their own files (`stdin.go`, `api.go`), so only A's rebases ripple.
- `internal/cmds/comments.go` is touched in sequence by A3 (call-site strip), C1 (verb), and F3 (anchor flags); the merge ledger's A→C→F order resolves it, no rebase rewriting.
- `internal/api/types.go` is owned by G; F extends `internal/api/pulls.go` only.
- `Ctx.Stdin` is owned by B; C and E only read the field.

F is the only branch whose design has an external input: the F1 probe run. Its output decides the wire encoding F2 commits, per the release doc's probe-first rule.

## Branches

### Branch A, v0.5.0-index-placement

Purpose: accept the numeric index wherever it appears on N-taking commands, through one scanner instead of per-command parsing. Position: first trunk; merges first, so every later branch rebases onto the new scan discipline once. Touch boundary: `internal/cmds/cmds.go`, every `parseIndex` call site (`pr.go`, `issues.go`, `comments.go`, `pr_conv.go`, `pr_diff.go`, `pr_merge.go`, `pr_review.go`, `pr_state.go`, `pr_resolve.go`, `pull.go`) and their tests, repo-root `version.go`. Forbids: a flag table inside the scanner, per-command index parsing, `--name=value` support, any behaviour change for existing argument orders.

Commits:

1. `chore: bump forge.Version to 0.5.0`: the release-doc convention in action; the binary, tag, and release doc agree from the first commit.
2. `feat(cmds): flag-aware index scan in parseIndex`: `parseIndex` keeps its signature and accepts the first numeric token wherever it appears, and `stripFlags` removes `--name value` pairs for named flags in one home. The scan alone is a superset of today's behaviour, so all existing call sites stay green.
3. `feat(cmds): strip value flags before the index scan at every N-taking command`: each call site strips its own value-taking flags first, which is why numeric flag values (`pr conv --min-unresolved 2 11`) are never mis-grabbed. Per-command tests cover index-first, flags-first, and numeric-flag-value orders.

### Branch B, v0.5.0-stdin

Purpose: give commands one context-borne input stream and one `-`-means-stdin helper. Position: second trunk; C and E both build on it. Touch boundary: `internal/cli/registry.go`, `cmd/forge/main.go`, new `internal/cmds/stdin.go`, `internal/cli` and `internal/cmds` tests. Forbids: reading stdin during wiring, any command consuming stdin that does not opt in, shell interpolation, a second input channel.

Commits:

1. `feat(cli): expose Stdin on Ctx`: main wires `os.Stdin`; tests substitute a reader; nil stays legal for commands that never read it.
2. `feat(cmds): one readDashInput helper for "-" values`: a flag value of `-` resolves through `ctx.Stdin`, nil stdin is a usage error, any other value passes through unchanged. Tests cover `-`, non-`-`, and nil-stdin cases.

## Abstractions and what they absorb

- The single index scanner with a strip discipline: a new N-taking command calls `stripFlags` then `parseIndex` and inherits options-anywhere behaviour; changing the numeric-token rule edits one function. Absorbs: new N-taking commands, a change to index acceptance rules.
- `readDashInput`: a new stdin-fed flag calls one helper instead of copying the `-` convention; changing nil-stdin policy edits one place. Absorbs: new stdin-reading flags.
